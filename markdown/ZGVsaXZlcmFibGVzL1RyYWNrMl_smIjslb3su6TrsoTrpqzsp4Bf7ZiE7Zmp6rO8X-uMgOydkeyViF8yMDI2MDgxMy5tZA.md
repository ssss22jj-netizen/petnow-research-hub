# Track 2 예약 커버리지 현황과 대응안 (2026-08-13)

## 1. 결론

- 폴의 예약 창을 KST 09:00~23:00으로 확대 시 미국 전 지역에서 사람이 진행하는 슬롯 확보 가능
- 확대 후에도 남는 구멍은 **미국 현지 업무시간(09:00~17:00)** 한 구간이며, 한국 시간 새벽 01:00~08:00에 해당해 사람으로 대응 불가
- 해당 구간은 AI 음성 에이전트의 데모 세션으로 대응

## 2. 현황

- 소재 B 첫 실유입 리드(애리조나 피닉스, 현지 8/13 00:21)가 폼 작성 완료 후 시간 미선택 이탈 — 예약 0건
- 원인 추정: 현재 예약 가능 시간이 06:00~09:30 ET로, 산악·태평양 시간대 리드에게는 현지 03:00~06:30 새벽에 해당. 리플레이상 날짜 11개를 순차 확인 후 미선택
- 조치안: 한국 오전(미국 서부 오후) 슬롯 추가 여부 결정 필요

- 첨부 캡처 판독 주의: 리플레이의 시간대 칸이 New York으로 보이나 재생 표시 오류이며, 실제 이벤트 조회 시 해당 세션의 접속 지역은 Arizona(Phoenix). book 페이지는 방문자 브라우저 시간대 기준으로 자동 설정되므로, 캡처의 03:00~06:30은 현지 시각 정상 표기
- 별건: 리플레이 판독 오류 2건(book 페이지 입력값 마스킹·시간대 표시) 수정 후 라이브 반영 완료. 신규 세션부터 적용

## 3. 근거 — 실유입 세션 기록

![소재 B 리드의 예약 화면 세션 리플레이 (2026-08-13, 애리조나 피닉스)](assets/replay_arizona_20260813.png)

- 화면의 예약 가능 시각: 03:00 ~ 06:30 (30분 간격 8칸)
- 서버 실측 슬롯: 06:00 ~ 09:30 ET (동일 날짜 8칸). 두 값의 차이 3시간은 피닉스(MST, UTC-7)와 동부(EDT, UTC-4)의 시차와 일치
- 교차 확인: 캡처 좌측의 기기 식별자 `$device:255145d5-57f1-4fa2-…`로 조회한 결과, 같은 세션 이벤트 10건의 `$city` 값이 모두 `Phoenix`, `$region` 값이 모두 `Arizona`
- 보조 근거: 리플레이에 남은 날짜별 슬롯 개수(8/17 8칸, 8/18 3칸, 8/26 2칸, 8/27 8칸)가 서버 실측치와 전부 일치 — 리드가 본 데이터와 현재 설정이 동일함을 확인
- 행동 기록: 날짜 11개(8/14~8/31)를 순차 확인한 뒤 시간 미선택 종료. 세션 길이 3분 33초

## 4. 예약 창별 미국 현지 시각 비교

8월 기준(미국 서머타임 적용). 애리조나는 서머타임 미적용으로 태평양과 동일 오프셋.

| 지역 | 현재 창<br>06:00~09:30 ET | 확대 창<br>KST 09:00~23:00 | 확대 후 쓸 만한 구간 |
| --- | --- | --- | --- |
| Eastern (UTC-4) | 06:00 ~ 09:30 | 전날 20:00 ~ 당일 10:00 | 저녁 20:00~23:00, 아침 07:00~10:00 |
| Central (UTC-5) | 05:00 ~ 08:30 | 전날 19:00 ~ 당일 09:00 | 저녁 19:00~22:00, 아침 07:00~09:00 |
| Mountain / 덴버 (UTC-6) | 04:00 ~ 07:30 | 전날 18:00 ~ 당일 08:00 | 저녁 18:00~21:00, 아침 07:00~08:00 |
| Pacific / 애리조나 (UTC-7) | 03:00 ~ 06:30 | 전날 17:00 ~ 당일 07:00 | 저녁 17:00~20:00, 아침 06:00~07:00 |

- 현재 창은 동부 외 지역에서 사실상 예약 불가. 태평양·애리조나는 전 구간이 현지 새벽
- 확대 창은 전 지역에 저녁 시간대를 개방. 임보·자원봉사 기반 조직은 주간 근무 인력 비중이 높아 저녁 접촉 가능성이 업무시간보다 낮지 않음
- 확대 창으로도 열리지 않는 구간은 현지 09:00~17:00(= KST 01:00~08:00)

## 5. 보이스 에이전트 데모 활용안

- 현지 업무시간 슬롯은 AI 음성 에이전트가 데모 투어를 진행하고 화면 반응·응답을 수집
- 예약 화면에서 진행 주체(사람/AI)를 슬롯 단위로 명시하고, 세션 말미에 팀 후속 연결 의향을 확인해 폴의 인터뷰 대상으로 인계

## 6. 구현

원칙: 폴이 가능한 시간은 폴에게 우선 배정하고, 나머지 시간만 에이전트가 담당.

| 순서 | 대상 | 작업 내용 | 선행 조건 |
| --- | --- | --- | --- |
| 1 | Cal.com 스케줄 | 예약 창을 KST 09:00~23:00으로 확대 | 폴 승인 |
| 2 | Apps Script `action=slots` | 폴 슬롯에 `host:"paul"`, 방문자 현지 09:00~17:00 중 폴 시간과 겹치지 않는 구간에 `host:"agent"` 부여 후 병합 반환 | 없음 |
| 3 | `/book/` 화면 | 슬롯 버튼에 진행 주체 표시, 확인 요약줄에 안내 1행 추가. 화면 구조 변경 없음 | 2 |
| 4 | Apps Script `action=book` | `paul`은 기존 Cal.com 예약 유지. `agent`는 시트 기록 + 확인 메일 + 세션 링크 발송(캘린더 API 미사용) | 에이전트 세션 형태 확정 |
| 5 | 계측 | 시트 `session_host` 컬럼 추가, Mixpanel `Booking Completed`에 동일 속성 부여 | 없음 |

- 2·3·5는 에이전트 형태와 무관하게 선행 가능
- 검증 순서: 개발 사이트(`petify-internal.pages.dev`)에서 전 구간 확인 후 라이브 반영. 광고 집행 중이므로 미검증 푸시 금지
