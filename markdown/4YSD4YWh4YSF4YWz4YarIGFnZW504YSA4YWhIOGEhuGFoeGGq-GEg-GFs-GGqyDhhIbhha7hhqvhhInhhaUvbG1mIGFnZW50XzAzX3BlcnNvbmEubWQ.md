- 제품/서비스: Petnow Shelter CRM
- 분석 기반: `brand_research.md`, `user_interview.md` (경쟁사 리뷰 40개 + **Gina 인터뷰 78분**)

## 페르소나 1: 다이앤 (Diane) — 대표 / Executive Director ✅ 검증

**실물 대응**: Gina Kim-Sadiku, KK9R CEO

### 기본 정보
- **직무**: 연 intake 200~600마리 규모 레스큐의 대표. 조직에 오래 관여하다 최근 대표가 된 경우가 많다
- **업무 패턴**: 전체 현황·성과·예산을 본다. **CRM 일상 입력자가 아니다** — Gina는 CRM 오류에 직접 개입한 사례를 기억하지 못했다
- **정보 탐색 습관**: 업계 네트워크·파트너 조직·grant maker. LinkedIn은 "직원들이 쓴다더라" 수준의 간접 인지

### 문제 상황 (Pain Point) — 로컬 공통 형태

- **어떤 개가 다음 단계로 갈 준비가 됐는지 판단이 안 돼서 게시가 밀린다**
- 의료·행동·사진·서류가 **여러 사람에게 흩어져** 있어 조각으로 들어온다
- 서버가 3일씩 내려가도 대안이 없다
- 사람이 바뀌면 정보가 같이 사라진다

> 🔴 **크로스보더 특수 (제외)**: KK9R에서는 이 문제가 *번역 부재 + 양국 팀이 개를 직접 못 봄* 으로 증폭돼 "수년 대기"가 됐다. 로컬에서는 같은 문제가 **"며칠~몇 주 지연"** 규모일 수 있다. 통증 강도는 미검증. → `crossborder_reference.md`

### 니즈 (Needs)
- 어떤 개가 다음 단계로 갈 준비가 됐는지 **판단 가능한 상태**
- 조각난 정보(건강·행동·사진·영상·허가)가 한 곳에 모일 것
- 최종적으로 **개가 더 빨리 입양되는 것**

### 기존 해결책 (Alternative)
Petstablished + Pawlytics(백업) + Airtable + DocuSign + Slack + 스프레드시트

### 구매 결정 요인
- **역할 변화가 트리거다** — Gina는 CEO 취임 3개월 시점에 문제를 발견하고 개발을 추진했다
- 파트너·타 조직과의 **호환성이 1순위 장벽**
- 예산 승인 권한은 **강할 것으로 보이나 미확인** — 만족도를 지불의향으로 읽으면 안 된다

### 대표 발언
> `"I want to say clogged system, but definitely dogs that are overlooked in the system that have been waiting at our shelter for many years"`
> `"this would benefit getting the dogs adopted faster"`
> `"Compatibility with partners or other organizations."` — 전환 장벽 1위
> `"No, I had no idea."` — 이 제품이 상용화될 줄 몰랐다

## 페르소나 2: 조 (Joe) — 시스템 실무자 / 도입 챔피언 ✅ 검증 **[v1 신규]**

**실물 대응**: Joe Amodio (KK9R). Gina의 추천 표현 — *"조직 내 정식 직함이 없어도 software를 가장 잘 아는 tech person"*

### 기본 정보
- **직무**: 정식 직함은 운영·입양 담당인데, 실질적으로 **조직의 시스템 담당**이다. CRM에 매일 입력하고, 새 도구를 조사하고, 대표에게 보고한다
- **업무 패턴**: intake 입력 → 상태 분류 → 사진·영상 업로드 → 외부 사이트 게시. 도구 사이를 오간다
- **정보 탐색 습관**: 직접 검색·비교·데모 신청. **플랫폼 비교 보고서를 쓰는 사람**

### 문제 상황 (Pain Point)
- 사진을 한 번에 못 올린다
- 서버가 내려가면 API를 다른 제품으로 돌려야 한다
- 같은 정보를 Petstablished·Airtable·Slack에 나눠 넣는다
- 대안을 조사해봤지만 **요구를 충족하는 제품이 없었다**

### 니즈 (Needs)
- 외부 게시(Petfinder·Adopt-a-Pet·웹사이트) 연동이 **실시간**일 것
- 다운타임이 없을 것
- 미디어 업로드가 일괄로 될 것
- 마이그레이션이 안전할 것

### 기존 해결책 (Alternative)
Petstablished(주) + Pawlytics(백업·과거 데이터) + Airtable + Slack

### 구매 결정 요인
- **직접 사지 않는다. 평가하고 추천한다.** 대표가 그 의견을 매우 중요하게 본다
- 평가 기준은 감성이 아니라 **작동 여부** — API 반영 속도, 다운타임, 업로드, 상태 분류
- Pawlytics는 UI가 더 좋았는데도 **API 반영이 12~24시간 걸려 탈락**시켰다

### 대표 발언
> `"They were down for three days."`
> `"It's ridiculous and very frustrating."`
> `"It's not like you can just upload all the pictures at once."`

### ⚠️ 아직 인터뷰 안 함
Joe 본인 인터뷰는 아직이다(연락 허가는 확보). **위 내용은 Gina를 통해 전해 들은 것**이다.

## 페르소나 3: 메건 (Megan) — 임보 코디네이터 🟡 가설 (미검증)

### 기본 정보

- KK9R에서는 이 기능을 **Airtable(첫 7일 foster diary) + Slack**이 담당한다. **CRM 밖에 있다**

### 문제 상황 (Pain Point)

- 임보자가 보낸 기록이 여러 채널에 흩어진다
- 임보자 가용 상태가 최신이 아니다

### 니즈 (Needs)
- 독촉 없이 기록이 모이는 구조 / 이상만 올라오는 화면

### 기존 해결책 (Alternative)
Airtable + Slack + 문자·메신저

### 구매 결정 요인
불명. v0에서는 이 사람을 챔피언으로 봤으나 **KK9R에서는 조가 챔피언이었다.**

### 대표 발언
> (경쟁사 리뷰) `"unable to make changes"`, `"currently using google spreadsheets"`

### ⚠️ 검증 상태
- KK9R에 **foster diary 담당자가 존재한다는 것은 확인**됐다 (Airtable로 운영)
- 그러나 이 사람이 **별도 역할인지, 겸직인지, 도입에 영향을 주는지 미확인**
- 디브리프 권장 후속 인터뷰 D(Foster 담당자 30~45분)로 확인해야 한다

## v0 → v1에서 바뀐 것

| | v0 (리서치 기반) | v1 (Gina 인터뷰 반영) |
|---|---|---|
| 챔피언 | 임보 코디네이터 (메건) | **시스템 실무자 (조)** |
| 구매 트리거 | 사건 (동물 놓침·감사) | **역할 변화** (신임 대표가 통합 추진) |
| 광고 1순위 타겟 | 메건 | **조** |
| 메건의 지위 | 검증된 챔피언 | 미검증 가설로 강등 |

> **왜 중요한가**: 조와 메건은 반응하는 언어가 다르다. 메건은 감정적 피로("또 문자")에, 조는 **작동 사실**(API 반영 속도, 다운타임, 업로드 방식)에 반응한다. 광고 카피의 톤이 달라진다.
