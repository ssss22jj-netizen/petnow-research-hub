# 경쟁사 리뷰·데모 UI·UX 전문가 패널 토론 기록

> **한 줄 결론:** 패널은 펫나우가 기존 쉘터 CRM의 기능을 다시 만드는 것보다 현장 기록과 운영 상태를 연결하는 보완 제품의 가능성을 우선 검증해야 한다고 판단함.

## 문서 역할

이 문서는 경쟁사 리뷰 분석과 데모 UI·UX 분석을 함께 검토한 전문가 패널의 토론 과정·이견·근거 수준을 보존하는 별첨임. 제품 분석 결론은 [경쟁사 데모 제품 UI·UX 통합분석](경쟁사_데모_UIUX_통합분석.md)에 반영함.

> 아래 내용은 실제 전문가 자문이나 인터뷰가 아니라 공개 연구와 프로젝트 자료를 바탕으로 전문가 관점을 재구성한 모의 토론임.

## 4. 패널 공통 판단

### 4.1 상태 정합성 우선

**[Moderate]**

- 리뷰 근거: 기록 최신화 실패, 외부 스프레드시트·이메일 사용, 사람·동물·조직 관계 단절
- 데모 근거: 동물 등록과 임보 배치 분리, 저장값 불일치, 저장 결과 불명확
- 패널 판단: 하나의 현장 사건이 동물 상태·현재 위치·담당자·관계·후속 업무·변경 이력을 함께 갱신하는 구조 필요

### 4.2 예외 복구 우선

**[Emerging]**

- 리뷰 근거: 중복 기록, 설정, 데이터 이관, 지원 과정의 높은 부담
- 데모 근거: 필드 초기화, 설정 미완료로 과업 차단, 저장 무반응 관찰
- 패널 판단: 정상 과업 완료 시간과 함께 입력값 보존·미완료 재개·변경 비교·이전 상태 복원 검증 필요

### 4.3 역할 간 업무 인계 우선

**[Moderate]**

- 리뷰 근거: 현장 기록 최신화와 담당자 간 전달 문제
- 데모 근거: 운영자 화면은 확인했으나 임보자 직접 입력부터 운영자 반영까지 전체 흐름 미확인
- 패널 판단: 모바일 반응형 여부보다 임보자 입력→운영자 확인→상태·후속 업무 반영의 완결성 우선

### 4.4 기존 CRM 병행 사용 우선

**[Moderate]**

- 리뷰 근거: 데이터 이전·교육·결제·외부 연동의 높은 전환 장벽
- 데모 근거: 기존 제품이 이미 넓은 기능 범위와 깊은 업무 이력 제공
- 패널 판단: 전체 CRM 교체보다 현장 기록을 구조화해 기존 CRM에 반영하는 보완 계층 우선 검증

## 5. 패널 내 이견

### 임보 중심 단체를 초기 고객군으로 설정할 것인가

**[Contested]**

- 찬성: 임보 중심 구조에서는 현장과 사무실 사이의 정보 단절과 모바일 입력 필요성이 명확함.
- 반대: 현재 근거가 KK9R과 제한된 리뷰·데모에 집중되어 전체 시장으로 일반화하기 어려움.
- 합의: 임보 중심 보호단체를 초기 고객군 후보로 설정하되 추가 인터뷰 전 시장 전체 결론으로 표현하지 않음.

### 자동 동기화를 초기부터 제공할 것인가

**[Contested]**

- 찬성: 기존 CRM에 다시 입력해야 하면 보완 제품의 가치가 약해짐.
- 반대: 경쟁사별 데이터 구조 차이로 초기 개발 범위가 급격히 증가할 수 있음.
- 합의: 초기에는 운영자가 변경 내용을 확인한 뒤 내보내고, 사용 빈도가 높은 시스템부터 제한적으로 동기화.

### 빠른 등록을 핵심 메시지로 사용할 것인가

**[Expert] 직접 구매 의향 근거가 제한된 경험 기반 판단임.**

- 단순 속도 메시지는 경쟁 제품도 주장 가능함.
- 저장 신뢰성, 상태 최신화와 담당자 인계가 실제 운영 가치에 가까움.
- ‘빠른 입력’보다 ‘누락 없는 현장 기록과 후속 업무 연결’을 우선 검증.

## 6. 권장 검증 지표

| 지표 | 측정 정의 |
| --- | --- |
| 과업 완료 시간 | 현장 사건 발생부터 운영자 확인 완료까지의 시간 |
| 재입력 횟수 | 동일 정보를 두 번 이상 입력한 횟수 |
| 확인 연락 횟수 | 누락·불명확 정보로 발생한 추가 연락 |
| 상태 불일치 건수 | 실제 위치·담당자·처리 상태와 시스템 기록의 차이 |
| 미완료 복구율 | 중단된 과업을 사용자가 다시 완료한 비율 |
| 병행 사용 의향 | 기존 CRM 교체와 별도로 보완 제품을 사용할 의향 |
