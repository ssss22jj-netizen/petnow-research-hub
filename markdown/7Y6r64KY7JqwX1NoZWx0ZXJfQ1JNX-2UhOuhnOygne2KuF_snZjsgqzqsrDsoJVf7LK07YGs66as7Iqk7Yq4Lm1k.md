# Petnow Shelter CRM 프로젝트 의사결정 체크리스트

- 사용 대상: 펫나우 경영진·제품팀·사업팀, 마켓핏랩
- 사용 시점: 주간 리뷰, 인터뷰·실험 종료 후, 다음 단계 착수 전
- 사용 목적: 프로젝트 진행 중 기능과 개별 의견에 매몰되지 않고 사업 목적·고객·문제·제품 진입점·지불가치에 대한 상위 판단 유지

## 한 줄 결론

**이 프로젝트의 핵심은 많은 기능을 정하는 것이 아니라, 어떤 고객의 어떤 반복 문제를 어떤 사업 목적으로 해결할지 증거를 바탕으로 좁혀가는 데 있다.**

## 체크리스트 사용 원칙

- 체크 완료 기준: 의견 합의가 아니라 판단을 뒷받침하는 실제 사례·행동·수치 확보
- 판단 보류 기준: 데스크리서치·경쟁사 데모·단일 고객 의견만 있고 실제 사용자 반복 증거가 없는 상태
- 기록 단위: `현재 판단 / 근거 / 반대 근거 / 결정 책임자 / 재검토일`을 함께 기록
- 방향 변경 기준: 기존 가설을 지지하는 증거보다 반대 증거가 강할 경우 변경·축소·중단 검토
- 범위 관리 기준: 아래 의사결정과 직접 연결되지 않는 기능 요구는 즉시 개발하지 않고 별도 백로그로 이동

상태 표기:

- `[ ]` 판단 전
- `[~]` 근거 수집 중
- `[x]` 판단 완료
- `[!]` 반대 증거 확인·재검토 필요

## 1. 사업 목적과 성공 기준

### 펫나우팀이 결정할 항목

- [ ] Shelter CRM의 1차 목적을 `독립 SaaS 매출`과 `현장 침투·데이터 축적·B2G 진입` 중 하나로 정하거나, 두 목적의 실행 순서를 확정했는가
- [ ] 선택한 사업 목적에 맞는 12개월 성공지표를 정했는가
  - 독립 SaaS: 유료 고객 수, ARR, 유료 전환율, 유지율
  - 침투·데이터·B2G: 목표 지역 활성 조직 수, 반복 사용률, 데이터 최신성·완전성, 공공기관 협의 진전
- [ ] 가격·무료 배포·온프레미스·데이터 활용 요구가 충돌할 때 적용할 우선순위를 정했는가

### 판단 완료 기준

- 경영진이 1차 목적, 성공지표, 목적 간 충돌 시 우선순위를 문장으로 승인
- 제품팀과 사업팀이 동일한 성공 기준 사용

> **방향 이탈 신호**: 독립 SaaS와 B2G의 성공지표를 동시에 사용하면서 가격·제품 범위·진입 지역의 우선순위가 계속 바뀌는 상태

---

## 2. 초기 고객군과 핵심 역할

### 펫나우팀이 결정할 항목

- [ ] 초기 고객군을 조직 유형·규모·운영 방식·지역 기준으로 한 문장에 정의했는가
- [ ] KK9R의 크로스보더 특수 문제와 미국 로컬 쉘터·레스큐의 공통 문제를 분리했는가
- [ ] 실제 사용자, 문제 책임자, 도입 추진자, 예산 결정권자를 구분했는가
- [ ] 초기 공략 대상에서 제외할 조직 유형을 명시했는가

### 판단 완료 기준

- KK9R 외 서로 다른 미국 로컬 조직 3곳 이상에서 유사한 업무 문제 확인
- 조직 특성과 문제 강도 사이의 관계 확인
- 사용자와 구매자의 요구가 다를 경우 각각의 도입 조건 정리

> **방향 이탈 신호**: 접근하기 쉬운 조직을 초기 고객군으로 정의하거나, Gina 개인의 요구를 전체 시장 수요로 간주하는 상태

---

## 3. 해결할 핵심 문제와 진입 과업

### 펫나우팀이 결정할 항목

- [ ] 고객이 최근 실제로 겪은 반복 문제를 하나의 업무 사건으로 정의했는가
- [ ] 문제의 발생 빈도, 건당 소요시간, 오류·지연 영향과 현재 우회 방법을 확인했는가
- [ ] 여러 문제 후보 중 첫 번째로 해결할 과업 하나를 선택했는가
- [ ] 선택하지 않은 문제 후보를 명시하고 후순위로 둔 이유를 기록했는가

### 강한 문제 판정 기준

- 서로 다른 조직에서 반복되는 최근 사례 존재
- 현재 CRM 외부의 시트·문자·메신저·수작업 등 우회 행동 존재
- 시간·누락·독촉·대기·오류 중 하나 이상 측정 가능
- 문제 해결이 운영 결과 또는 구매 검토로 연결

> **방향 이탈 신호**: 사용자가 원하는 기능 목록을 문제 증거로 간주하거나, 하나의 진입 과업을 선택하지 않은 채 범용 CRM 기능을 확대하는 상태

---

## 4. 제품 진입 방식과 범위

### 펫나우팀이 결정할 항목

- [ ] 기존 CRM을 전면 교체할지, 특정 과업을 해결하는 연동형 모듈로 진입할지 정했는가
- [ ] 선택한 진입 과업의 시작·종료 조건과 사용자 역할을 정의했는가
- [ ] 기존 CRM·결제·마이크로칩·외부 게시 채널 중 반드시 유지하거나 연동해야 할 대상을 정했는가
- [ ] 모바일 지원을 화면 반응형 여부가 아니라 역할별 과업 완료 기준으로 정의했는가
- [ ] 데이터 이전·권한·감사 이력 등 도입 필수조건과 후순위 기능을 구분했는가

### 판단 완료 기준

- 고객이 기존 도구를 유지한 상태에서도 시험 가능한 최소 범위 확정
- 경쟁제품보다 완료시간·단계·재입력·누락을 얼마나 줄일지 목표 설정
- 제품 범위에 포함하지 않을 기능 명시

> **방향 이탈 신호**: 경쟁사 기능표의 빈칸을 채우는 방식으로 로드맵을 정하거나, 기존 시스템과의 공존 조건을 확인하지 않고 전면 교체를 전제하는 상태

---

## 5. 지불가치와 사업성

### 펫나우팀이 결정할 항목

- [ ] 고객의 현재 소프트웨어·수작업 비용과 예산 승인 구조를 확인했는가
- [ ] 어떤 업무 결과가 확인되면 고객이 비용을 지불할지 정의했는가
- [ ] 월 $99 등 가격 가정을 경쟁사 구독료가 아니라 고객의 순가치와 비교했는가
- [ ] 결제·기부·마이크로칩 혜택 등 경쟁제품의 전체 경제 구조를 반영했는가
- [ ] 무료 사용 의향과 실제 지불 의향을 구분하기 위한 유료 행동을 요청했는가

### 판단 완료 기준

- 가격 범위와 구매 조건을 예산 결정권자에게 직접 확인
- 유료 파일럿, 계약 검토, 예산 배정 등 비용이 수반되는 행동 확보
- 절감시간·오류 감소·수익 증가·위험 감소 중 가격을 설명할 가치지표 확정

> **방향 이탈 신호**: 제품 만족도나 무료 사용 의향을 지불 의향으로 해석하거나, 경쟁사보다 기능이 많다는 이유만으로 가격을 결정하는 상태

---

## 6. 데이터·비문 인식·B2G 확장 조건

### 펫나우팀이 결정할 항목

- [ ] 현장 사용 과정에서 어떤 개체 데이터가 어떤 빈도와 품질로 축적되는지 확인했는가
- [ ] 펫나우가 데이터 분석·비문 인식·공공사업에 활용할 수 있는 동의와 권리를 확보할 수 있는가
- [ ] 비문 인식이 실제 업무에서 사용되는 시점과 기존 식별수단 대비 역할을 정의했는가
- [ ] B2G 진입 대상 지역과 공공기관이 필요로 하는 구체적 의사결정·업무를 정했는가
- [ ] 무료 배포로 얻는 지역 침투·데이터 가치가 포기하는 SaaS 매출보다 큰지 판단했는가

### 판단 완료 기준

- 데이터 수집 목적·권리·품질·보존·활용 범위에 대한 내부 기준 확정
- 공공기관의 구체적 활용 의사 또는 검토 조건 확인
- SaaS 제품의 핵심 가치와 비문·B2G 확장 가치를 분리 평가

> **방향 이탈 신호**: 데이터 활용 권리와 공공 수요를 확인하지 않은 채 CRM 설치 수 자체를 B2G 가능성으로 간주하는 상태

## 7. 파일럿 이후 계속·전환·중단 판단

### 펫나우팀이 결정할 항목

- [ ] 실험 시작 전에 성공·실패·판단 보류 기준을 정했는가
- [ ] 인터뷰 발언보다 실제 사용·반복 사용·결제·소개 행동을 우선 증거로 사용했는가
- [ ] 가설을 지지하는 증거와 반대하는 증거를 함께 검토했는가
- [ ] 다음 단계 판단을 `계속 / 고객군 변경 / 문제 변경 / 제품 방식 변경 / 중단` 중 하나로 기록했는가
- [ ] 판단 결과에 따라 다음 4주간 하지 않을 일을 정했는가

### 다음 단계 진입 기준

| 판단 | 적용 조건 | 다음 행동 |
| --- | --- | --- |
| 계속 | 동일 고객군에서 반복 문제·사용 행동·지불 신호 확인 | 선택 과업의 제품화·유료 파일럿 확대 |
| 고객군 변경 | 문제는 강하지만 현재 고객군의 예산·접근성 부족 | 동일 문제를 더 크게 겪는 조직 탐색 |
| 문제 변경 | 고객군은 적합하지만 선택 문제가 낮은 우선순위 | 다음 문제 후보 검증 |
| 제품 방식 변경 | 문제는 강하지만 전면 교체·연동 방식이 도입을 차단 | 모듈·서비스·연동 범위 재설계 |
| 중단 | 반복 문제·행동 변화·지불 신호가 모두 부족 | 투자 중단 또는 다른 사업 가설로 전환 |

모든 판단을 지금 내릴 필요는 없다. 각 영역의 결정에 필요한 증거가 모이는 시점 기준.

| 판단 영역 | 권장 판단 시점 | 이유 |
| --- | --- | --- |
| 사업 목적 (§1) | M1 종료 온사이트 전까지 잠정 서열 합의 | 리서치 증거가 아니라 경영 의지의 문제. 서열이 없으면 이후 모든 판단이 흔들림 |
| 초기 고객군 (§2) | 로컬 쉘터 인터뷰 종료 후 | KK9R 단독으로는 크로스보더 특수성과 공통 문제를 분리할 수 없음 |
| 핵심 문제 (§3) | 인터뷰 종료 후 M1 리포트에서 후보 압축 | 병목별 빈도·소요시간·우회 행동 증거 필요 |
| 제품 진입 방식 (§4) | Gina 인터뷰 결과 확인 후 | 기존 CRM 해지 조건과 병행 실태 확인이 선행 |
| 가격·지불가치 (§5) | Gina 인터뷰 WTP 결과 확인 후 | $99의 출처(원가 기준인지, 가정인지) 확인과 조건부 지불의향 증거 필요 |
| 데이터·비문·B2G (§6) | 사업 목적(§1) 서열 결정과 함께 | 비문 인식의 역할 정의는 축 서열에 종속 |
| 계속·전환·중단 (§7) | 파일럿 시작 전 (필수) | 기준 없이 시작하면 결과 해석이 사후 합리화가 됨 |

- **유력**: 복수 자료가 같은 방향을 가리키지만 현장 반복성·사업가치 미확인
- **초기 가설**: 데스크리서치·경쟁사 데모·단일 사례에서 도출
- **미확인**: 판단에 필요한 자료 없음
