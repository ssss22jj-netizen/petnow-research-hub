# Petify for Shelters 포지셔닝 정의 — Chameleon · 24PetShelter · Petszel 대비

- 작성일: 2026.08.20
- 성격: 경쟁 포지셔닝 판단 자료 (내부 검토용)
- 근거: Chameleon 화면 10점 직접 판독 · 24PetShelter 화면 6점 및 공개 기능 전수 · 자사 데모 UI 전수 · Petszel 공개 자료·지원문서 전수
- 수록 범위: 9절에 M2에서 신규 조사한 제품(Chameleon/24PetShelter · Petszel) 종합을 함께 수록함
- 근거 등급: 화면·기능 목록은 직접 확인 [검증됨·L0], 제품 철학 해석은 판단 [의견·L4]

## 1. 결론

- 3사는 동일 시장의 경쟁 관계가 아니라 **각기 다른 업무 구간을 주무대로 삼는 제품**임
- 내부 가설(“24PetShelter는 정보 관리 중심, 자사는 흐름 관리 중심”)은 **지지됨**. 단 정보 대 흐름의 대비로는 절반만 설명되며, 3사를 동일 기준으로 비교하려면 **주무대 구간**을 축으로 삼아야 함

| 제품 | 주무대 | 제품 본질 | 성공 정의 |
| --- | --- | --- | --- |
| Chameleon/CMS | 기관 법정 의무 전 구간 | 원장(ledger) — 면허·출동·수납·감사 기록 | 감사·규제 대응 가능한 기록 확보 |
| 24PetShelter | 출구(outcome) | 거래 — 입양 처리·체크아웃·칩 등록 | 입양 건의 무마찰 처리 |
| Petify for Shelters 데모 | 출구 이전(in-care) | 준비 파이프라인 — 요건 판정·대기열·담당자 | 차단 항목 해소를 통한 게시 가능 상태 도달 |

- **3사 모두 보호 기간 중 진행 상태를 판정하는 기능 층이 부재함.** 자사 진입 지점에 해당

## 2. 24PetShelter — 레코드와 거래로 구성

공개 기능 그룹 6종이 전부 레코드 또는 거래에 해당함. 화면 제목도 `manage`로 시작하는 형태로 일관됨.

| 기능 그룹 | 항목 | 성격 |
| --- | --- | --- |
| Animal Management | 프로필 생성·사진/영상 업로드·태그·시설 내 위치 | 레코드 |
| Medical, Notes, Reporting | 표준 의료 템플릿·메모 추적·통계 대시보드 | 레코드 + 집계 |
| Intakes & Outcomes | 가이드형 입소·아웃컴 기록·노트/이력 | 레코드 |
| User & Organization | 계정 설정·역할 기반 권한 | 설정 |
| Adoption & Checkout | 디지털 입양 워크플로·Mobile Checkout·영수증 | 거래 |
| Integrated Value | 24Petwatch 칩 등록·PetPlace 생태계 연결 | 거래 |

- 제공 대시보드는 `Stats dashboard for key shelter metrics` 1종으로 **통계 집계이며 작업 대기열이 아님**

### 2.1 반례 후보 검토

| 후보 | 검토 결과 |
| --- | --- |
| 상단 탭 `Action Center` | 명칭과 달리 **작업 수행 영역**으로 판단됨. 해당 탭 하위에 Animal Profile·Animal Medical Record 화면이 배치됨. 할 일 대기열로 볼 근거 없음 [추정·L2, 화면 2점 기준] |
| Care Item의 `Next Due` | 항목별 다음 예정일은 존재(예: `Rabies 3 Year / Next Due: Oct 24, 2027`). 단 **동물 단위로 미충족 항목을 집계해 상태를 판정하는 층은 미확인** |

### 2.2 구조의 배경 — 수익모델

- 소프트웨어 정기 요금 없음. **입양 1건당 $5 + 입양 건당 무료 마이크로칩 + PetPlace 생태계(펫보험 등)** 로 수익 발생
- 24PetShelter 제품 페이지에 입양자 대상 `Review & Pay 3/3` 보험 가입 화면이 수록됨. 화면 자체는 **PetPlace**(동일 모기업의 소비자 브랜드, 「24Pet by PetPlace」) 표기임 — 24PetShelter 관리자 화면이 아니라 체크아웃 이후 입양자가 이어지는 다음 단계 화면 [검증됨·L0, 이미지 직접 확인]
- 입양 건 처리가 매출 조건이므로 체크아웃·영수증·계약이 1차 출시에 포함되고, 준비 과정 관리가 후순위로 배치되는 것은 정합적 선택임 [의견·L4]
- 향후 수개월 내 출시 예정 기능: over-the-counter 거래, 외부 결제수단, 다중 아웃컴, 계약서 유형 추가, 고급 권한, **포스터 관리, 온라인 리스팅, 켄넬 카드**

## 3. Chameleon의 포지셔닝 — 동일 계보, 상이한 무게중심

**판정: 세계관은 동일하나 주무대가 다름.** 24PetShelter가 입양 거래를 주무대로 삼는 데 비해, Chameleon의 주무대는 기관이 법적으로 보존해야 하는 기록 전체임.

| 축 | Chameleon/CMS | 24PetShelter |
| --- | --- | --- |
| 고객 | 지방정부 동물통제기관·공공 쉘터 | 소규모·단순 운영 조직 (초기 릴리스 기준) |
| 기능 무게중심 | 면허·현장출동·위반장·물림 신고·수납·감사 | 입소·의료·입양 체크아웃 |
| 수익 구조 | 라이선스·구축·유지보수 (견적형) | 입양당 과금 + 칩·보험 생태계 |
| 시간 개념 | 출동 단계별 타임스탬프, 면허 갱신 주기 | Care Item의 `Next Due` |
| 입양의 위치 | 수납 화면 `Procedures` 메뉴의 `Finalize Adoption` | 제품 중심 동선 |

- **공통점**: 입양을 케어의 종결이 아니라 거래의 종결로 모델링함. 20년 간격에도 동일하게 유지됨
- **차이점**: Chameleon은 거래보다 규제 준수와 원장 정확성이 우선이며, UI가 코드·감사·수납 중심으로 고착됨

### 3.1 Chameleon 내 “다음 행동” 요소 (대응 시 주의)

전무하지 않음. 단 **전부 기관 의무 축에 귀속되며 개체 준비 상태 축이 아님.** 데모 현장에서 “알림 기능 부재”로 진술할 경우 반박 가능성 있음.

| 요소 | 실제 내용 | 한계 |
| --- | --- | --- |
| Chameleon Mailbox | 데이터 오류·면허 갱신·레스큐 통지 자동 메일 | 대상이 면허와 데이터 정합성 |
| WebChameleon 켄넬 인벤토리 | `Last Checked: 73 days` 적색 표시 | 최종 점검 시각 단일 지표. 부족 항목·담당자 미표시 |
| `Procedures` 중복 처리 | 중복 레코드 제출·병합이 상시 메뉴로 배치 | 데이터 위생 업무이며 개체 진행 관리 아님 |

## 4. 3사 공통 미대응 구간

```
입소 ──[ 보호 중 · in-care ]── 출구
 │                                │
 Chameleon: 기록                   Chameleon: 수납·아웃컴 코드
 24PetShelter: 가이드형 입소        24PetShelter: 체크아웃·칩·영수증
                     ↑
              판정 기능 층 부재
```

| 제품 | 보호 기간 중 대응 수준 |
| --- | --- |
| Chameleon | 상태는 `Status`·`Condition` 코드 1칸, 성격은 `Temper` 1칸. 켄넬 뷰는 개체 정보 없는 색상 블록 |
| 24PetShelter | 해당 구간 기능(포스터 관리·온라인 리스팅·켄넬 카드) 미출시 |
| Petify for Shelters 데모 | 해당 구간을 주무대로 설정 |

## 5. 자사 차별 요소 — 흐름이 아니라 판정

기존 서술(“단일 흐름”, “다음 행동 우선”)은 결과 기술에 해당하며, 이를 생성하는 메커니즘은 다음과 같음.

> 조직이 **준비 완료 기준을 직접 편집**(Health 30일·Behavior 14일·공개용 사진 3장) → 룰이 **상태를 자동 판정** → 미충족 항목이 **대기열로 전환** → 각 행에 **사유·담당자·다음 행동**을 부착

- 24PetShelter에서는 해당 판정이 성립 불가함. `Ready to publish` 상태가 성립하려면 게시 요건 정의가 선행되어야 하나 온라인 리스팅 자체가 미출시 상태임
- 부가 차별 요소 2건

| 요소 | 자사 데모 | 24PetShelter |
| --- | --- | --- |
| 기록 반영 방식 | 체크인 제출을 공식 기록과 좌우 대조 후 부분 승인해야 반영 | 각 카드의 `Edit`로 직접 편집 |
| 조직 외부 데이터 수집 | 계정 불요 임보자 전용 링크·1탭 제출 | 포스터 관리 자체가 미출시 |

## 8. 미확인 사항

1. 24PetShelter `Action Center`의 실제 성격 — 작업 수행 영역 여부, 할 일 대기열 포함 여부
2. `Next Due` 미충족 항목의 동물 단위 집계 화면 존재 여부
3. 포스터 관리·온라인 리스팅의 출시 시점과 설계 방향
4. 공공기관 고객의 이전 가능성 — 신제품에 면허·출동·수납 기능이 없어 **당분간 Chameleon 잔류 가능성이 높음.** 산타바바라 카운티 판단에 직접 영향

### 9.1 Petszel — 다른 시간축의 무료 레이어

- **한 줄 결론**: 기능이 겹치지 않음. 겹치는 것은 구매자·연동 표면·과금 앵커, 그리고 “예약 발송 설문 → 예외만 담당자 알림”이라는 작동 메커니즘
- 커버 구간이 입양 **후**(성사 시점~1년)로, 자사의 입양 **전**(보호 중) 구간과 시간축이 분리됨
- 쉘터·입양자 전원 무료 — 수익원은 입양자 구독(TeleAdvice)·브랜드 파트너(Hill’s)·프로바이더 연결 3계통으로 추정됨
- 4대 쉘터 관리 시스템(PetPoint·ShelterLuv·ShelterBuddy·Chameleon)에 API 직결 완료. 자사는 미구축 상태라는 점이 실행 함의로 남음
- 힐스(Hill's Food, Shelter & Love)는 수익원인 동시에 **유입 채널**임 — 힐스 전용 랜딩이 월간 입양 보고 자동화를 전면에 세우고 입양 후 지원은 `Optional`로 분리 배치. 문을 여는 것은 보고 자동화이며, 개별 아웃바운드 대비 접점 비용 우위를 만듦 [검증됨·L0]
- 작동 메커니즘의 실체는 단순 설문 발송이 아니라 **이진 사실 기준의 알림 트리거**임 — 대부분의 응답은 대시보드에만 적재하고, “물거나 할퀴어서 피부가 찢어졌다” 같은 판단이 필요 없는 응답에서만 담당자에게 알림. 소재 B의 “예외만 담당자에게”가 풀어야 할 문제(예외의 정의)를 이 제품이 어떻게 내렸는지 보여줌 (상세: 화면 판독 문서 4.1절)
- 위협은 기능 잠식보다 **가격 앵커링**(쉘터가 “이 범주는 무료”로 학습) 쪽이 큼

| 경쟁 성격 | 같은 시장, 다른 주무대(원장·거래 vs 준비 파이프라인) | 다른 시장(쉘터 관리 SW 위의 레이어), 같은 구매자 |
| 임보 커버 | 켄넬 격자의 부속 취급 — 실질적 공백 | 지원문서에 임보 항목 없음 — 공백 |
| 가격 압력 | 견적형(Chameleon) / 입양당 과금(24PetShelter) | 전원 무료 — “이 범주는 무료”라는 인식 형성 위험 |
| 데모 콜 활용 | Chameleon 사용 조직 앞에서 주무대 대조 | “Petszel 사용 여부”를 스크리닝 질문으로 추가 |

- **공통 시사점**: 임보(foster) 축이 두 조사 모두에서 미점유로 확인됨. 지금까지 M2 제품 조사에서 가장 일관되게 반복된 결과이며, 소재 B(임보 체크인)의 빈자리에 해당함
- 단, Petszel은 자사 발표 외 검증 자료가 없어 대외 문서에서 “경쟁사 미커버”를 단정하지 않음
