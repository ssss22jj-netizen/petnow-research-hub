## 한 줄 결론

**Petszel은 Petify for Shelters와 기능이 겹치지 않는다. 겹치는 것은 구매자·연동 표면·과금 앵커, 그리고 "예약 발송 설문 → 예외만 담당자 알림"이라는 작동 메커니즘이다.** 현 시점 직접 경쟁이 아니라, 임보 영역으로 인접 확장 시 정면으로 겹치는 후보다.

화면 쪽 결론은 하나 더 있다 — **입양자에게 읽을 것과 연결할 곳을 주는 앱이지, 입양자가 무언가를 기록하게 만드는 앱이 아니다.**

## 2. 조사 방법과 한계

- 쉘터 대시보드·설문 결과 화면은 계정이 있어야 접근 가능. **가짜 쉘터로 가입하지 않음**
- 지원문서 60여 편에 **제품 UI 스크린샷이 한 장도 없음** — 벤더가 화면으로 팔지 않는다
- 마케팅 페이지 이미지는 대부분 스톡 사진. 실제 UI 근거는 히어로 목업 1장과 데모영상뿐
- 따라서 화면 판독은 **입양자 앱에 한정**되며, 쉘터 측 사용성은 판정하지 않음
- 리뷰 플랫폼(Capterra·G2 등)에 제품 등재·리뷰가 확인되지 않아, 경쟁4사처럼 리뷰 기반 질적 분석 불가
- 근거 등급: 화면 구조·라벨·탭 구성은 프레임 직접 판독 `[검증됨·L0]`. 대시보드 구조·설문 응답률·과금 단가는 미확인. 설계 의도 해석은 `[의견·L4]`

## 3. 사업 모델 — "쉘터에 안 받는" 구조

- 쉘터·레스큐·입양자 **전원 무료**. 계정 생성·입양 패킷·설문·대시보드·프로바이더 등록 모두 과금 없음(공식 FAQ 명시)
- 수익원 3계통

| 계통 | 내용 | 근거 수준 |
|---|---|---|
| ① 입양자 구독 | TeleAdvice(24/7 수의 테크니션 상담) 입양 후 30일 무료 → 이후 월 구독 전환 | `[검증됨·L0]` 공식 FAQ. 단가는 미공개 |

### 5.1 온보딩 실제 절차 `[검증됨·L0]`

- 쉘터 관리 시스템에 전용 사용자 계정 생성(PetPoint 기준: 사람 레코드 추가 → Employee 연결 → 사용자 권한 부여) → 그 계정 정보를 Petszel 대시보드에 입력
- 로고 업로드, 지역 병원 목록 등록, 지원 수준(우리 팀 회신 / 지역 파트너 전달) 설정
- 입양자 연락 동의는 쉘터 관리 시스템의 `Do Not Contact`·`Do Not Call` 값을 그대로 읽어감
- 힐스 경로에서는 **설문 하나 작성 후 벤더가 연결을 대행**한다고 명시

> 셋업 자체는 반나절 수준이다. 도입에 오래 걸린 사례가 있다면 기술 난이도 때문이 아니라는 방증이다.

## 6. 화면 판독 — 입양자 앱

### 6.1 홈 — 체크리스트가 첫 화면이다

- 상단: 쉘터 로고 + Petszel 컬러바. 좌측 햄버거, 우측 `Switch Pet`
- 좌상단 `Check-Ins` 아이콘에 **미처리 건수 빨간 배지**
- 동물 아바타 + `Welcome home, Daisy!` + 2줄 안내문
- **온보딩 체크리스트 3항목** — `Let's get acquainted`(2m onboarding, 완료) · `Check-In: Day One`(2m survey) · `Read: "Rule of 3" article`(2m read)
- 하단에 `Easy Vet Care` 예약 배너, `Pet Care Providers` 카드
- 하단 탭 5개: `Profile` `Guide` `Daisy` `Pet Care` `Folder`

**판독** — 설문을 이메일로 따로 보내는 구조가 아니라 **앱 첫 화면의 할 일 목록에 얹었다.** 각 항목에 예상 소요시간을 붙여 진입장벽을 낮춤. 가운데 탭에 동물 이름을 넣어 앱 전체를 한 마리 중심으로 묶음 `[의견·L4]`

### 6.2 Folder — 서류 보관함

- `Daisy's Folder` 아래 접이식 2개 — `Medical Records` / `Adoption Packet`(`Adoption Contract (PDF)` · `Dog Adoption Guide` · `Adopter Resources`)
- 그 아래 `Articles` 카드 3개, 일부는 영상 재생 아이콘

**판독** — 종이 입양 패킷을 그대로 디지털로 옮긴 화면. 별도 화면에서 `DaisyMedRecs.pdf` 라는 **의료 요약 PDF 다운로드**가 확인됨. 기록을 앱 안에 가두지 않고 PDF로 내보내는 설계 `[검증됨·L0]`

### 6.3 아티클 상세

- 상단 이미지 + 집필자 배지(`Dr. Mike Greenberg` — Petszel CVO)
- 제목 `Rule of Three`, 우측 `Video Version ▶` 토글 — 같은 콘텐츠를 글/영상 중 선택

### 6.4 Pet Care — 지역 병원 지도

- 지도 위 핀 + 반경 원, 우측에 병원 카드 목록(별점·주소·전화·`BOOK ONLINE NOW`)
- 상단 `Find a Veterinarian` 검색 + 필터

**판독** — 이 목록은 **쉘터가 직접 등록**하고 추천·오퍼·차단 상태를 쉘터가 지정한다. 화면에서는 그 통제가 보이지 않고 자연스러운 추천으로 읽힘 `[검증됨·L0 문서 / 의견·L4 해석]`

### 6.5 TeleAdvice — 영상 상담

- 전체화면 영상통화 UI. 하단 3버튼(스피커·카메라·종료). 상단 쉘터 로고 유지
- 입양 후 30일 무료, 이후 입양자 월 구독 — **쉘터 브랜드 화면 안에서 유료 전환이 일어난다** `[검증됨·L0]`

### 6.6 기부 폼 — 유일하게 입력을 요구하는 화면

- `One Time`/`Monthly` 토글, 금액 버튼(`$5`~`$50`) + 직접 입력, 이름·이메일·전화·카드 정보
- 앱 전체에서 **입양자가 키보드를 쓰는 유일한 화면.** 상태 보고·기록 입력을 요구하는 화면은 없음

### 6.7 입양자에게 가는 이메일

- 발신 쉘터명, 본문 상단에 쉘터 로고 + 작게 `Powered by Petszel`
- 축하 문구 + 동물 사진 + `VIEW DAISY'S APP` 버튼
- 입양자 시점에서 이것은 **쉘터가 보낸 메일**이다

## 7. 쉘터가 보는 화면 — 알림 트리거

확인된 쉘터 측 화면은 **이메일 알림 한 장**뿐이다. 화면 내용은 `New message!` / `Rachel Smith · Kit · Challenges With Pet Introductions` / `Open`. 제목에 주제 유형(행동·의료·일반)과 입양 지점을 넣어 수신함 필터로 팀 라우팅이 가능하게 설계돼 있다. **이메일은 알림이며 데이터 연동 통로가 아니다** — 버튼은 제품으로 들어가는 링크다.

이 제품에서 실제로 정교한 부분은 이메일이 아니라 **무엇을 알림으로 올릴지 고르는 규칙**이다.

| 설문 | 알림이 가는 응답 | 알림이 가지 않는 응답 |
| --- | --- | --- |
| Day 1 | 후속 연락 요청에서 `행동·훈련 지원`·`의료 문의`·`기타` 선택 | 만족도·NPS·매칭 이유 등 나머지 전 항목 |
| Week 1 · Month 1 | 공격성 보고 후 상세 질문에서 **"물거나 할퀴어서 피부가 찢어졌다"** | 으르렁거림·놀이 물기·겁먹고 스냅·다른 동물과의 충돌 |
| Month 2 | 위 + 계속 키울지 질문에서 **"지금 도움이 필요하다"** | "잠깐 스친 적 있다" 수준 |
| Month 3 | 위 + **"걱정된다"** 까지 확대 | 동일 |

**판독** `[검증됨·L0]`

- **기본값이 침묵** — 설문 8회를 돌리면서도 대부분의 응답은 대시보드에만 적재
- 알림 기준이 심각도 판단이 아니라 **누가 답해도 같은 값이 나오는 사실**로 내려와 있음
- 트리거되는 순간 입양자에게 **연락처와 상세를 받아냄** — 알림에 후속 재료가 이미 붙어 있음
- 시간이 갈수록 임계값을 낮춤(Month 2 "지금 도움 필요" → Month 3 "걱정된다")

**주의** — 쉘터 직원이 대시보드에 로그인하지 않는 상태를 벤더가 **관리해야 할 이탈로 인식**하고 있다. 지원문서는 "이메일은 개요일 뿐, 자세한 내용은 대시보드에 로그인"이라고 명시하고, 월간 요약 메일 안내에 "최근 로그인하지 않았다면 이 메일이 좋은 리마인더"라는 문장을 둔다. 즉 *긴급 건은 메일로 밀고 나머지는 대시보드에 쌓이며, 대시보드 방문율은 벤더의 과제로 남아 있는 구조* `[검증됨·L0]`

## 9. 마케팅 페이지 판독

### 9.1 쉘터용 랜딩

- 히어로: `Shelter-branded post-adoption app` + `BOOK A WALK-THROUGH` / `SIGN UP NOW`
- 중단 카피: **`Get started in minutes. No downloads. It's free.`**
- 기능 4개를 글머리표로만 나열. **대시보드 스크린샷 없음**
- 실명 후기: San Diego Humane(Director of Operational Programs) 등

### 9.2 힐스 전용 랜딩 — 실제 유입 경로

- 헤드라인: `You care for the pets. We'll handle the paperwork and reporting.`
- 도식: `Your adopter spreadsheet → Now automated by Petszel → sent to Hill's`
- 온보딩 3단계: ①`Check the fit—no commitment needed` ②`Connect—zero tech headaches`(설문 하나 채우면 벤더가 연결) ③`Set it and forget it`
- 효익: **`Save 10+ hours per month`**, 데이터 입력 불필요, 힐스 요건 자동 준수
- 실명 후기: Louisiana SPCA COO — "직원 한 명을 다른 데이터 업무로 돌릴 수 있었다"
- 입양 후 지원은 페이지 하단에 **`Optional`** 로 분리 배치

**판독** — 힐스 월간 보고 자동화가 문을 열고, 입양 후 지원은 옵션으로 얹는 land-and-expand 구조. 힐스는 수익원인 동시에 **유입 채널**이다 `[검증됨·L0]`

## 10. Petify for Shelters와의 관계

### 10.1 겹치지 않는 것 (제품)

| 구분 | Petify for Shelters | Petszel |
|---|---|---|
| 시간축 | 입양 **전** — 보호 중 동물 상태·잔여 과업 | 입양 **후** — 입양자 적응 |
| 소재 A 영역 | 동물 1마리의 건강·행동·사진·서류를 한 화면에, 다음 할 일 가시화 | 해당 없음 |
| 소재 B 영역 | 임보자 정기 체크인 링크, 예외만 담당자에게 | 해당 없음 |
| 진실 원장 | 동물 레코드 자체를 보유 지향 | 쉘터 관리 시스템 위에 얹히는 레이어 |
| 임보 취급 | 핵심 | 지원문서 전수에 임보 항목 없음 `[추론·L2 — 공개 문서 부재 기준]` |
| 사용자 입력 | 임보자가 **매주 정보를 넣어야** 성립 | 입력을 요구하는 화면이 기부 폼뿐 |

### 10.2 겹치는 것 (전장)

1. **구매자 동일** — 쉘터 운영·입양 담당자
2. **연동 표면 동일** — 4대 쉘터 관리 시스템. Petszel은 구축 완료, Petify는 미구축
3. **작동 메커니즘 동일** — 예약 발송 설문 → 정상 응답은 자동 적재 → 예외만 담당자 알림
4. **가격 앵커 동일 지점** — 쉘터 대상 무료

### 10.3 위협 판정

| 위협 | 판정 | 근거 |
|---|---|---|
| 기능 잠식(현재) | **낮음** | 커버 구간이 입양 전/후로 분리. 현 공개 제품에 임보·보호 중 운영 없음 |
| 인접 확장(임보 체크인) | **중간** | 설문·알림·SMS 엔진 보유. 대상만 입양자→임보자로 바꾸면 형태는 성립. 단 임보 데이터는 쉘터 관리 시스템에 없어 API 연동만으로는 못 채움 `[추론·L2]` |
| 가격 앵커링 | **중간~높음** | 쉘터가 "이 범주는 무료"로 학습 |
| 채널 선점 | **중간** | 힐스 프로그램 보고 자동화를 통로로 쉘터 대량 온보딩. 개별 아웃바운드 대비 접점 비용 우위 |

## 11. M2 실행 함의

- **리드 자격 질문 추가** — 데모콜 스크리닝에 "Petszel 사용 여부". 사용 중인 곳은 외부 도구 연동·설문 운영에 이미 익숙 → 도입 저항이 낮은 세그먼트
- **무료 앵커 대응** — "왜 유료인가"가 아니라 "무엇의 원장인가"로 프레임 분리. Petszel은 쉘터 관리 시스템 위의 레이어, Petify는 보호 중 기록 자체를 다루는 도구
- **차용 ① 소요시간 표기** — `2m survey`처럼 걸리는 시간을 항목마다 붙여 응답 저항을 낮추는 방식은 임보 체크인에 그대로 이식 가능
- **차용 ② 예외를 사실로 정의** — "심각한가"를 응답자에게 판단시키지 않고 관찰 가능한 이진 사실로 알림 기준을 내리고, 트리거 시 연락처·상세를 그 자리에서 받아냄. 소재 B의 "예외만 담당자에게"가 실제로 풀어야 할 문제가 이것
- **차용 ③ 기록의 출구를 PDF로** — 앱 안에 기록을 가두지 않고 요약 PDF로 내보냄. Jared가 요구한 `Petify → PDF → PetPoint` 인계와 같은 형태
- **기준선으로 삼지 말 것** — Petszel 앱은 입양자에게 입력을 거의 요구하지 않는다. 임보 체크인은 반대다. 같은 "간단한 링크 하나"로 보여도 요구하는 행동의 무게가 달라, Petszel의 응답률·도입 속도를 우리 기준선으로 쓸 수 없다 `[의견·L4]`
- **세일즈 화법** — Petszel을 이미 쓰는 조직에는 "Petszel이 입양 후에 하는 일을 보호·임보 기간에 하는 도구"라는 설명이 이미 통했음(Jared 인터뷰에서 본인이 먼저 그렇게 정리)
- **대외 문서 주의** — 자사 발표 외 검증 자료가 없으므로 "경쟁사가 임보를 커버하지 않는다"를 단정하지 않음
