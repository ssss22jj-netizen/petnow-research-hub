# Love’s Legacy Rescue 인터뷰 인사이트

> **정기적으로 임보자의 사진·행동·상태 정보를 받고 미응답자에게 다시 연락하는 자동화는 Love’s Legacy의 실제 업무에 잘 맞는다.** Lara는 평균 입양 기간 단축과 임보자의 지속 참여를 지불 가치의 기준으로 제시했다. 다만 제품이 이 성과를 낸다는 근거, 월 $99~149의 가격 수용 여부, 파일럿 참여 확정은 아직 없다. 다음 대화에서는 운영 담당자들과 정기 정보 수집·팀 공유·Shelterluv 반영 과정을 구체화할 필요가 있다.

본문의 영어 인용은 **인터뷰 보고서 수록 발언**이다. 원녹취는 확보되지 않았으며, 보고서의 고객 발언과 분석자가 제안한 기능·파일럿안을 구분했다.

## 2. 현재 업무 방식

Shelterluv가 공식 기록을 관리하고, 내부 운영진은 동물별 Slack 채널을 활용한다. 임보자와의 실제 대화는 주로 문자에서 이루어져, 임보자가 보낸 최신 정보와 담당자의 대응 내용을 팀 전체가 함께 파악하기 어렵다.

| 현재 업무 | 확인된 문제 |
| --- | --- |
| Shelterluv에서 동물·신청·자원봉사자 기록 관리 | 기준 기록은 정해져 있지만, 임보자가 보낸 최신 사진·행동·상태 정보는 개인 문자, 단체 문자, Slack, 공유 이메일에 나뉘어 있다. |
| 내부 운영진이 동물별 Slack 채널에서 소통 | Lara는 동물별 채널이 내부 상황 공유에 유용하다고 설명했다. 다만 Slack을 사용하지 않는 임보자의 정보가 자동으로 팀에 공유되지는 않는다. |
| 임보자가 특정 담당자에게 문자로 연락 | 담당자가 여행하거나 자리를 비우면 임보자에게 새 담당자를 안내해야 한다. 기존 대화가 원래 담당자의 문자에 남아 있어, 다른 팀원이 앞선 상황을 파악하기 어렵다. |
| 사진·행동·성격 정보를 필요할 때 요청 | 임보자는 주로 문제가 생겼을 때 먼저 연락한다. 운영진은 최근 소식을 들었는지, 누가 연락했는지, 새 사진을 받을 수 있는지 수시로 확인해야 한다. |
| 지역별로 연락할 임보자 선정 | 특정 지역에 있으며 현재 동물을 맡을 여력이 있는 임보자를 쉽게 찾기 어렵다. 지역 행사나 임보 요청을 안내할 때도 대상자를 별도로 구분한다. |
| Shelterluv 자료를 GiveButter로 옮겨 이메일·문자 발송 | Shelterluv에서 자료 내보내기, GiveButter로 가져오기, 대상자 구분, 발송을 수작업으로 진행한다. Lara는 원하는 방식으로 두 도구가 연결되지 않는 점을 불편으로 설명했다. |
| Petfinder·Adopt-a-Pet에 입양 정보 게시 | Lara는 현재 Petfinder가 Shelterluv와 연결되어 있지 않다고 설명했다. 입양에 활용할 최신 사진·행동·성격 정보를 임보자에게 받는 과정도 운영진이 직접 챙긴다. |

인테이크부터 입양까지의 모든 처리 단계나 단계별 소요 시간은 이번 보고서에 제시되지 않았다. 확인된 범위는 기준 기록 관리, 임보자와의 정보 교환, 팀 공유, 연락 대상자 선정, 입양 정보 활용이다.

## 3. 검증 대상

소재 B는 **임보자의 정기 응답을 수집하고, 응답하지 않은 임보자에게 다시 연락하는 일을 자동화할 수 있다**는 가설을 검증한다. Lara는 정해진 항목을 자동으로 요청하고 사진·세부 정보를 다시 요청하는 기능을 긍정적으로 평가했다. 임보자 정보 수집과 후속 확인이 실제 반복 업무라는 점은 구체적인 운영 사례로 확인된다.

| 검증 대상 | 결과 |
| --- | --- |
| 정기 정보 요청·미응답 확인의 부담 | 임보자가 먼저 일상 정보를 보내는 경우가 많지 않아, 운영진이 최근 소식과 사진을 요청해야 한다. 누가 연락했는지와 응답을 받았는지도 팀 안에서 다시 확인한다. |
| 임보자 정보의 팀 공유 | 개인 문자에 기존 대화가 남아 있어 담당자 부재 시 인계가 어렵다. 내부 Slack 채널은 유용하지만 임보자에게 받은 정보가 팀 전체에 자동으로 전달되지는 않는다. |
| 기존 CRM을 유지하는 보조 서비스의 수용 | Lara는 Shelterluv의 기준 기록 역할에 동의했고, 임보자 응답을 직원이 검토한 뒤 Shelterluv에 반영하는 데모에 긍정적으로 반응했다. Shelterluv를 교체해 달라는 요청은 없었다. |
| 비용을 지불할 가치의 기준 | Lara는 평균 입양 기간 단축과 임보자의 지속 참여를 제시했다. 사진·행동·성격 정보가 많을수록 입양을 돕는다고 설명했지만, Petify 사용 전후의 효과를 측정한 것은 아니다. |
| 파일럿·유료 사용 의사 | 제품과 팀원이 참여하는 후속 회의 제안에는 긍정적으로 답했다. 그러나 파일럿 참여를 명시적으로 확정하거나 월 $99~149를 수용한다는 답변은 보고서에 없다. |

> “Did you check in with so-and-so?”  
> “Have you heard from so-and-so?”  
> “Can you get updated pictures?”

Lara가 설명한 반복 확인 업무에 관한 **인터뷰 보고서 수록 발언**이다(§19). 임보자에게 연락했는지, 최근 소식을 받았는지, 새 사진을 확보했는지를 운영진이 서로 확인하는 상황을 보여준다.

> “Average time to adoption”  
> “Foster retention”

Petify에 비용을 지불할 가치가 있으려면 어떤 결과가 필요한지 묻는 질문에 Lara가 제시한 **인터뷰 보고서 수록 발언**이다(§9~10·23). 각각 평균 입양 기간과 임보자의 지속 참여를 뜻한다. 현재 기준값, 개선 목표, 측정 기간은 제시되지 않았다.

> “really limited”

Shelterluv API에 대한 Lara의 **인터뷰 보고서 수록 발언**이다(§13). API는 다른 소프트웨어와 데이터를 주고받는 연결 수단이다. 이 발언은 Lara가 원하는 연동에 제약을 겪고 있다는 설명이며, Petify에 필요한 동물·임보 배정 정보 조회나 사진·행동 기록 반영이 불가능하다는 기술 검증 결과는 아니다.

| 도입 전 확인할 조건 | Shelterluv와 어떤 정보를 주고받을 수 있는지, 운영 담당자들이 정기 정보 수집·검토·기록 반영을 어떻게 분담할지 확인해야 한다. 지역·현재 수용 여력에 따라 임보자를 찾는 업무도 구체적으로 확인할 필요가 있다. |
| 지불 의향 | Johnny가 예상 가격 월 $99~149와 추가 맞춤 개발 시 비용 증가 가능성을 설명했다. Lara는 가격에 대한 별도 반대나 수용 의사를 밝히지 않았다. 지불 가치의 기준은 제시했지만, 실제 예산·현재 도구 비용·지불 가능한 금액·유료 전환 의향은 답하지 않았다. |
| 마무리 | 후속 회의와 팀원 초대 제안에 “That sounds good.”이라고 답했다(인터뷰 보고서 수록 발언, §22). 제품에 대한 호감과 후속 대화 의사는 확인되지만, 파일럿 참여 확정으로 기록할 수는 없다. |

## 5. 발언 뒤에 있는 것

- **소재 B의 가치는 정기적인 정보 확보와 후속 확인에 있다.** [해석·L2] 운영진이 사진·행동·성격 정보를 필요할 때마다 요청하는 구조에서는 입양에 활용할 자료가 안정적으로 쌓이기 어렵다. 정기 요청, 미응답 알림, 수신 정보의 팀 공유가 현재 업무에 직접 연결된다. 펫나우는 메시지 발송 기능의 선호보다 실제 정보 확보와 확인 업무의 변화를 검증할 수 있다.
- **팀 전체가 확인해야 하는 범위는 임보자에게 받은 정보와 담당자의 대응 내용이다.** [해석·L2] 동물별 Slack 채널은 이미 내부 운영진에게 유용하다. 이번 사례에서 Slack 전체를 대체해야 한다는 근거는 없으며, 임보자와 담당자의 개인 문자에 남은 정보를 팀이 함께 확인하도록 돕는 역할이 더 적합하다. 이 역할을 구현하는 구체적인 방식이나 Slack 연동까지 고객과 합의한 것은 아니다.
- **입양 기간과 임보 지속 참여는 구매 가치의 기준이며, 아직 제품 효과는 아니다.** [해석·L2] Lara는 더 많은 사진·행동·성격 정보가 입양을 돕는다고 설명했다. 이 발언만으로 정기 체크인이 평균 입양 기간을 줄이거나 임보 지속 참여율을 높인다고 결론 낼 수 없다. 특히 Petfinder 자동 게시의 효과와 임보 정보 확보의 효과는 별도로 확인해야 한다.
- **Shelterluv 유지와 정보 연동이 도입 검토의 중심이다.** [해석·L2] Lara는 Shelterluv가 기준 기록이라는 점과 Petify가 기존 시스템을 보완하는 역할을 받아들였다. 다만 API가 제한적이라는 사용자 경험만으로 필요한 연동의 가능 여부를 결정할 수 없다. 동물·임보 배정 정보를 읽는 범위와 검토된 사진·행동·메모를 기록하는 범위를 각각 확인해야 한다.
- **지역별 검색과 수용 여력 확인은 별도 업무로 범위를 정할 필요가 있다.** [해석·L2] 특정 지역에서 동물을 맡을 수 있는 임보자를 찾기 어렵다는 불편은 직접 제시됐다. 그러나 자동 매칭 방식, 수용 가능한 동물 유형, 정보 갱신 주기까지 구체적으로 요청한 것은 아니다. 우선 지역별 연락 대상 선정과 현재 수용 여력 확인 과정을 검토해야 한다.
- **추가 구독의 구매 가능성은 별도 확인이 필요하다.** [해석·L2] 가치 기준을 제시한 것은 일반적인 제품 호감보다 구체적인 신호다. 다만 이사회·재무 직책, 3개월 무료 파일럿에 대한 긍정 반응, 가격에 반대하지 않았다는 사실 중 어느 것도 구매 권한·가격 수용·유료 전환을 확정하지 않는다.

## 6. 언급된 기능 요청

아래 표는 Lara가 설명한 불편, 질문한 항목, 데모에서 유용하다고 평가한 기능을 기록한다. 각 항목을 모두 직접적인 개발 요청으로 해석하거나 반영 우선순위를 정한 표는 아니다.

| 기능 요청 | 발언 맥락 |

| 정기 체크인·미응답 알림 자동화 | Lara는 구조화되고 자동화된 요청과 사진·세부 정보 알림이 도움이 된다고 설명했다. 임보자에게 먼저 연락하고 재확인하는 일이 현재 반복 업무다. |
| 사진·행동·성격·상태 정보 수집 | 임보자가 문제가 생겼을 때 주로 연락해 운영진이 정보를 별도로 요청한다. Lara는 사진·행동·성격 정보가 충분할수록 입양을 돕는다고 설명했다. |
| 임보자 정보의 팀 공유·이력 확인 | 담당자 부재 시 새 담당자를 안내해야 하고, 이전 대화가 원래 담당자의 문자에 남는 문제를 설명했다. 구체적인 공유 화면이나 이력 구조를 요청한 것은 아니다. |
| Shelterluv에 검토된 정보 반영 | 직원이 임보자의 응답을 검토한 뒤 Shelterluv에 반영하는 데모에 긍정적으로 반응했다. 모든 응답을 반드시 승인해야 한다고 직접 요청한 것은 아니다. |
| 지역·현재 수용 여력에 따른 임보자 검색 | 특정 지역에서 현재 동물을 맡을 수 있는 임보자를 쉽게 찾지 못하는 점을 불편으로 설명했다. 지역별 행사·임보 요청 안내를 위해 대상자를 구분해야 한다. |
| 이메일·문자 발송을 위한 자료 이동 개선 | Shelterluv에서 GiveButter로 자료를 내보내고 가져오는 수작업을 설명했다. GiveButter의 기부자 관리 기능 전체를 대체해 달라는 요청은 없었다. |
| 입양 게시에 수집 정보 활용 | 임보자에게 받은 사진·정보가 Shelterluv나 Petfinder에 이어지는 데모를 유용하게 평가했다. Adopt-a-Pet은 현재 사용하는 도구로 언급했으며, 별도 자동 게시 기능을 직접 요청한 것으로 기록하지 않는다. |
| 모바일 접근 | Petify가 모바일 앱인지 질문했고, Shelterluv의 모바일 사용이 불편하다고 설명했다. 모바일 접근성만을 핵심 구매 이유로 제시하지는 않았다. |

보고서의 기능 분류에 포함된 **별도 앱 설치·로그인 없는 사용, 응답 검토 화면, 임보자 매칭**은 고객이 모두 직접 요청한 항목으로 확인되지 않는다. 이 기능의 필요성과 구체적인 사용 조건은 후속 검토에서 구분해야 한다.

## 7. 남은 것

1. **Lara와 실제 운영 담당자가 참여하는 후속 회의를 확정한다.** 후속 대화에 대한 긍정 답변과 실제 예약·참여를 구분한다. 파일럿을 시작하려면 참여 의사, 담당자, 대상 임보자·동물, 사용할 기간과 범위를 명시적으로 합의해야 한다.
2. **정기 정보 수집부터 팀 공유까지의 실제 업무를 확인한다.** 요청 항목, 발송 주기, 미응답자 재연락 기준, 수신 정보의 검토 담당자, 담당자 부재 시 인계 방식, Shelterluv에 남겨야 하는 기록을 운영진과 함께 정한다. 지역별 대상 선정과 현재 수용 여력 확인도 이 과정에서 구체화한다.
3. **Shelterluv 연동 범위를 기술적으로 확인한다.** 동물·임보자·임보 배정 정보를 조회할 수 있는지, 검토된 메모·행동·사진을 어떤 항목에 기록할 수 있는지 확인한다. 가능한 범위에 맞춰 구현안을 정하고, Petfinder 자동 게시 포함 여부는 실제 연동 조건과 현재 게시 업무량을 확인한 뒤 판단한다.
4. **업무 개선과 최종 성과를 나누어 측정한다.** 우선 정기 요청 발송·미응답 확인에 드는 시간, 사진·행동·성격 정보의 확보 빈도, 팀원이 최신 정보를 찾거나 인계받는 데 드는 시간을 지표 후보로 검토한다. 평균 입양 기간과 임보자의 지속 참여는 Lara가 제시한 가치 기준에 따라 현재값·계산 방식·측정 기간을 별도로 정한다.
5. **지불 조건과 승인 구조를 확인한다.** 월 $99~149를 지속적으로 부담할 수 있는지, 어떤 성과가 어느 정도 개선돼야 구매를 검토할지, 최종 결정자와 승인 절차가 누구에게 있는지 확인한다. 현재 Shelterluv·GiveButter 관련 비용도 추가 구독을 판단하는 맥락에서 확인한다.

위 후속 업무와 측정 지표는 **분석 제안**이다. 원보고서 §20~21의 파일럿 범위·가설 역시 고객과 합의한 실행 계획으로 볼 수 없다. 이번 콜에서 확인된 것은 정기 정보 수집 자동화에 대한 긍정 반응과 성과 기준이며, 파일럿 참여·도입 범위·측정 계획은 후속 합의가 필요하다.
