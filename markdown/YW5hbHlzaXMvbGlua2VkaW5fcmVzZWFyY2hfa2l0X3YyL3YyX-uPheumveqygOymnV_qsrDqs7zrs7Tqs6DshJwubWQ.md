# LinkedIn 탐색환경 v2 독립 검증 결과

> 결론: 조직 기반 탐색은 원시 후보 확보 공수를 크게 줄였으나, 로그인 LinkedIn 상세 검증이 없으면 고신뢰 최종 목록을 만들 수 없음. v2 최종본은 원시 후보와 검증 완료 후보를 분리하고, 직책·프로필 직접검증이 없는 행을 QA 오류로 차단하도록 보정함.

## 1. 독립 실행 결과

| 항목 | 결과 |
| --- | ---: |
| Tier A 조직 완료 | 20/20개, 100% |
| 필수 검색 로그 | Q001~Q005 100건 |
| 보완 검색 로그 | Q006 8건 |
| 공개 검색 원시 발견 | 200명 이상 |
| 조직별 상한 적용 후 CSV 수록 | 39명 |
| 구체적인 현재 직책 확인 | 9명 |
| 풀타임 직접 근거 확인 | 1명 |
| QA 초안 | 오류 0건 |
| QA 보정본 | 직책 미확인·프로필 직접검증 미완료 행 오류 처리 |

## 2. 기존 목록과 비교

| 지표 | v1 | v2 독립 실행 | 변화 |
| --- | ---: | ---: | ---: |
| 독립 실행 후보 | 23명 | 39명 | +16명 |
| 전체 53명과 공통 후보 | 2명 | 14명 | +12명 |
| 전체 후보 일치율 | 2.7% | 18.0% | +15.3%p |
| 전체 기존 목록 재현율 | 3.8% | 26.4% | +22.6%p |
| Tier A 기존 후보 재현율 | 해당 없음 | 45.2% | 신규 측정 |
| Tier A 조직 검색 완료율 | 미측정 | 100% | 신규 측정 |

Tier A 기존 후보는 기준 목록 31명이며, 독립 실행에서 14명을 재발견함.

## 3. 공수 결과

| 단계 | 결과 |
| --- | --- |
| Q001~Q005 배치 검색 | 약 3분 |
| 후보 선별·기록 | 약 2분 |
| 총 경과 | 약 5분 |
| 해석 | 자동 배치 검색 기준. 사람이 브라우저에서 수행할 때는 조직당 6~8분 상한 적용 필요 |

원시 후보 발견 공수는 충분히 낮아졌으나, 소개·경력 모두 표시·추천사·최근 활동과 고용형태를 확인하는 상세 검증 공수는 별도로 필요함.

## 4. 발견된 품질 문제

- 독립 세션이 `조직 소속(직함 미표시)` 프로필을 최종 후보에 포함
- 공개 검색 결과만으로 고용형태 직접 근거 확보 곤란
- LinkedIn 로그인 브라우저 미사용으로 경력 모두 표시·추천사·최근 활동 검증 미완료
- 39명이라는 수치가 검증 완료 인원으로 오해될 가능성

## 5. 보정 사항

| 보정 | 적용 결과 |
| --- | --- |
| 원시 후보 저장소 추가 | `discovery_pool_template.csv` 신설 |
| 최종 후보 편입 조건 강화 | 구체적인 현재 직책 확인 필수 |
| 로그인 검증 의무화 | 로그인 불가 시 최종 후보 생성 중단 |
| QA 강화 | `조직 소속`, `직함 미표시`, `미확인` 역할 오류 처리 |
| QA 강화 | `프로필 직접검증=완료`가 아니면 오류 처리 |

## 6. 최종 판단

- 후보 발견 효율: 통과
- Tier A 조직 탐색 완결성: 통과
- 기존 후보 재현성: v1 대비 개선, 목표 60%에는 미달
- 고신뢰 최종 후보 15명 확보: 미달
- 고객사 단독 운영 가능 조건: LinkedIn 로그인 세션과 상세 검증 단계 확보 필요

v2는 `5분 만에 39명 검증 완료` 환경이 아니라, `짧은 시간에 충분한 원시 후보를 확보하고 잘못된 후보가 최종 목록으로 넘어가지 못하게 하는 환경`으로 사용해야 함.
