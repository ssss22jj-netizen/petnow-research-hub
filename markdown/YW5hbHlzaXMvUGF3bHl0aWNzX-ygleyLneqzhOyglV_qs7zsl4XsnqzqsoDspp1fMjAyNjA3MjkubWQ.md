# Pawlytics 정식 계정 UI·UX 과업 검증

> 신규 동물 등록과 임보자 배치는 완료됐으나, 임보 위치와 동물 상태가 자동으로 연동되지 않았다. 모바일 화면은 데스크톱 구조를 축소해 표시하여 현장 과업 완결성이 낮았다.

- 검증 일자: 2026-07-29
- 검증 환경: Pawlytics 정식 운영 계정의 Chrome 로그인 세션
- 검증 데이터: `Codex Test Milo 0729`, `Codex Test Foster 0729`, `Codex Test Adopter 0729` 등 가상 데이터만 사용
- 안전 경계: 결제, 유료 전환, 계정 설정 변경, 외부 이메일 발송, 최종 입양 상태 변경 미수행
- 사진 업로드: Chrome 확장 프로그램의 파일 URL 접근 권한 제한으로 파일 선택 단계에서 중단

## 2. T1 신규 동물 등록 및 임보자 배치

### 수행 결과

- 가상 동물 `Codex Test Milo 0729` 생성 완료
- 내부 ID `CODEX-PW-0729`, 상태 `Needing Foster`, 견종 Labrador Retriever, 체중 44lb 저장
- 가상 임보자 `Codex Test Foster 0729` 생성 완료
- Foster·Available Foster 태그 저장
- 동물 Current Location에 가상 임보자 연결 완료
- Current Status를 `In Foster`로 별도 변경

### UI·UX 관찰

- 사람 레코드 저장 후 People 목록으로 이동하고 검색을 통해 저장 결과 확인 가능
- 임보 위치를 Foster로 변경해도 동물 상태는 `Needing Foster`로 유지
- 운영자가 Current Status 편집을 다시 열어 `In Foster`를 별도 선택해야 하는 구조
- 위치·상태 불일치가 실제 저장 상태로 발생하므로 단순 위험 추정이 아닌 재현된 결함성 마찰로 판정

### 리뷰 대조

- 사람 레코드 생성 어려움: 이번 과업에서는 관찰되지 않음
- 초기 학습 부담과 다단계 처리: 부분 재현
- 기록 불일치 가능성: 임보 위치와 상태의 불일치로 재현

## 3. T2 사진·투약·행동 기록 및 담당자 확인

### 수행 결과

- 가상 SVG 사진 파일 업로드 시도
- Chrome 확장 프로그램이 파일 선택을 허용하지 않아 Pawlytics 업로드 저장 미수행
- Medical Event에 다음 가상 투약 정보 저장
  - Amoxicillin 1 tablet twice daily
  - 식욕 모니터링
  - `Codex Test Foster 0729` 보고로 메모
- Notes에 다음 가상 행동 기록 저장
  - 실내에서 차분함
  - 다른 개와 만나기 전에 관찰 필요
- 행동 기록 작성자 `Johnny Shin`, 날짜·시간 표시 확인

### UI·UX 관찰

- 의료 기록은 필수 필드가 사실상 Reason for Medical Event 한 개여서 빠르게 저장 가능
- 투약명·용량·주기·투약 담당자를 구조화하지 않고 자유 텍스트 한 필드에 함께 기록
- 행동 기록도 자유 텍스트 중심
- 가상 임보자가 보고한 내용임을 메모에 수동 기재했지만 시스템 작성자는 운영자 `Johnny Shin`으로 표시
- 임보자의 직접 입력과 운영자 확인 흐름이 아니라 운영자의 대리 입력 흐름으로만 검증

### 리뷰 불만 재현

- 동물 기록의 중앙화와 기본 메모 편의성: 재현
- 의료 데이터 입력의 번거로움: 이번 단순 이벤트 입력에서는 미재현
- 역할 간 기록 인계의 불명확성: 임보자 보고와 시스템 작성자가 분리되어 부분 재현

## 4. T3 입양 신청부터 계약·결제·상태 변경

### 수행 결과

- Applications에서 실제 신청서 목록과 Adoption·Foster·Volunteer·Surrender 분류 확인
- 운영자 화면에서 신규 입양 신청서를 만드는 버튼은 확인하지 못함
- 가상 입양자 `Codex Test Adopter 0729` 사람 레코드 생성
- Adopter·Potential Adopter 태그 저장
- 테스트 동물의 Add Outcome Event에서 Adoption과 가상 입양자 선택
- `Create Outcome Event` 실행 직전 중단

### 안전 경계

화면 안내:

> We’ll send an email with the adoption attachments listed in your organization settings to Codex Test Adopter 0729.

- `Create Outcome Event` 실행 시 가상 입양자 이메일로 계약 첨부 발송
- 동물 Outcome과 상태가 입양 완료로 변경될 가능성
- 외부 이메일 발송과 동물 상태 변경이 결합된 버튼이므로 사용자 승인 필요
- 결제 기능은 Outcome 실행 전 화면에서 확인되지 않음

### 리뷰 불만 재현

- 입양 기능의 설정·외부 도구 의존성: 신청 생성 경로 미노출로 부분 재현
- 위험 동작의 결합: 계약 이메일과 Outcome 생성이 하나의 버튼에 결합되어 재현
- 결제와 상태 동기화: 실행 전 중단으로 판정 보류

## 5. 모바일 완결성

- 검증 뷰포트: 390×844px
- T1 동물 상세: 데스크톱 전체 페이지를 매우 작게 축소하여 왼쪽 일부에 표시
- T2 의료 기록: 기록 조회는 가능하나 작은 글자·터치 영역과 데스크톱 카드 폭 유지
- T3 입양 Outcome: 왼쪽 내비게이션이 화면 대부분을 덮고 모달 필드·안내 문구 일부가 가려짐
- 판정: 모바일 친화성 낮음
- 역할별 완결성:
  - 운영자 조회: 가능하나 확대·정밀 터치 필요
  - 임보자 직접 기록: 별도 임보자 세션 미확보로 미검증
  - 입양 Outcome 입력: UI 요소는 존재하지만 화면 중첩 때문에 실무 완결성 낮음
