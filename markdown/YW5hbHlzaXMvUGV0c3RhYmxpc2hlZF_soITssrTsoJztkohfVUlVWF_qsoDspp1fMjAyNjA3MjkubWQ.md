# Petstablished 전체 제품 UI·UX 검증

> Petstablished는 쉘터 운영 전반을 포괄하는 기능 범위와 일관된 목록 관리 패턴이 강점이나, 실제 운영 화면은 기능·설정·상업 기능이 한 제품에 누적돼 정보 밀도와 학습 부담이 높음. 430px 모바일에서는 조사한 37개 화면 모두 기본 페이지의 가로 오버플로가 없었지만, 의료 기록 모달 잘림과 최대 10,034px의 설정 화면이 확인돼 “반응형 화면 제공”과 “모바일 과업 완결성”을 구분해야 함.

| 항목 | 내용 |

| 검증일 | 2026-07-29 |

## 3. 공통 UI 패턴

### 3.1 강점

- **일관된 목록 화면 구조**: `Actions`, `Bulk Actions`, 검색, 정렬, 페이지당 건수, 필터, 보기 방식의 반복 적용
- **대량 운영 지원**: 전체 필터 결과 선택, 현재 페이지 선택, 기본 필터 저장, CSV·XLS 보고서 생성
- **사용자 정의 범위**: 동물·연락처 필드, 입소 요약, 문서·의료 태그, 신청 진행 상태의 조직별 설정
- **감사·운영 기능**: 직원, 업무, 알림, 활동 로그, 문서, 기부, 보고서의 독립 관리
- **비동기 보고서**: 보고서 생성 중 다른 화면 이용 가능, 완료 결과를 다운로드 목록에 보존
- **데이터 식별 수단**: 동물명, 내부 ID, 마이크로칩 번호를 통합 검색

### 3.2 주요 사용성 문제

| 문제 | 관찰 근거 | 영향 |
| --- | --- | --- |
| 기능별 화면 분산 | 동물 기본 정보, 의료, 입소 요약, 알림, 이송이 별도 목록 | 한 동물의 현재 상황 파악과 다음 행동 결정에 화면 왕복 필요 |
| 목록 화면 고밀도 | 기본 50건, 다수 필터·일괄 작업·보기 방식 제공 | 숙련자는 효율적이나 신규 사용자의 인지 부담 증가 |
| 관리자 설정 장문화 | Pet Defaults: 데스크톱 약 9,941px, 모바일 약 10,034px, 모바일 가시 컨트롤 136개 | 설정 누락·오입력·변경 영향 파악 부담 |
| 모바일 모달 결함 | 의료 기록 대상 동물 선택 모달의 제목과 `Create Record`가 오른쪽에서 잘림 | T2 의료 기록의 모바일 과업 완결성 저하 |
| 신청 운영의 대량 탐색 | 입양 신청 기본 50건, 현재 계정 26페이지 | 특정 신청 건의 우선순위·병목 파악 어려움 |
| 보고서 피드백 지연 | 대형 보고서는 최대 20분, 완료 확인을 위해 수동 새로고침 안내 | 생성 상태의 실시간 피드백 부족 |
| 상업 기능 혼재 | 결제 포털 홍보, 마이크로칩 구매, 도매 약국이 운영 화면에 노출 | 핵심 업무 집중도 저하 가능 |
| 설정 데이터 이상 노출 | 현재 계정의 동물 `Actions` 메뉴에 `Add …` 항목 1,608개 생성 | 메뉴 탐색 사실상 불가능. 계정 설정·데이터 오염 가능성이므로 제품 공통 결함으로 일반화 금지 |

## 4. 영역별 상세 분석

### 4.1 대시보드·온보딩

- 조직 통계, 날짜 필터, 위젯 표시·숨김, 새로고침 주기 제공
- 동물 수, 입양, 신청, 기부 등 운영 KPI 배치
- 대시보드와 튜토리얼의 기능 범위는 넓으나 정보량이 많고 주요 당일 업무의 우선순위 표현은 약함
- Tutorials & FAQ에 매뉴얼, 세미나, 다수 기능별 튜토리얼 제공

**판정**: 학습 자료는 충실하나 제품 자체의 단순성보다 별도 학습 자료에 의존하는 구조

### 4.2 동물·입소·의료·임보

- 동물 목록에서 검색, 정렬, 필터, 보기 방식, 일괄 선택 제공
- 동물 추가 상태에서 `Adopted`, `Fostered` 직접 선택 비활성화
- 임보자 지정 등 별도 절차를 통한 상태 변경 유도
- 의료 기록, 입소 요약, 알림, 조직 간 이송을 독립 목록으로 제공
- 의료 기록에 임보 담당자 연결 가능

**판정**: 데이터 기능은 풍부하나 동물 상세 중심의 통합 작업공간보다 기능별 목록 중심

### 4.3 신청·계약·결제

- 신청 상태: Pending, Denied, On Hold, Approved, Adopted, Fostered, Returned, Archived
- 신청 목록에서 담당자, 진행 상태, 동물, 신청자, 신청일, 결과일 기준 검색·정렬 가능
- 온라인 양식, 일반 양식 제출, 계약 템플릿, 제출 계약을 별도 관리
- 신청 상세에서 담당자·일반 양식·입양 계약 연결
- 입양비 결제 링크는 은행 계좌 설정 선행 필요

**판정**: 통제 가능한 단계 구조는 강점이나 신청→계약→결제→동물 상태 변경이 하나의 진행 화면으로 완결되지 않음

### 4.4 연락처·업무·문서·감사

- 연락처, 직원, 업무, 알림, 발송 메시지, 활동 로그를 독립 제공
- 문서 태그와 문서 목록을 분리해 분류 가능
- 역할·담당자 운영에 필요한 구성요소는 확보
- 기능별 메뉴 구조로 인해 “오늘 처리할 업무”와 “특정 동물·신청의 전체 이력” 사이의 전환 비용 발생

**판정**: 조직 관리 범위는 넓으나 역할별 작업대보다 데이터 객체별 관리도구에 가까움

### 4.5 보고서·기부

- 보호 동물 수, 입소·결과·임보, 동물·마이크로칩, 의료, 연락처·신청자·기부·사용자 그룹 보고서 제공
- 저장 보고서와 애플리케이션 양식 보고서 베타 제공
- CSV·XLS 생성, 생성 이력, 비동기 처리 제공
- 생성 중 화면 이탈 가능하나 완료 여부는 수동 새로고침 필요

**판정**: 분석 범위는 강점. 보고서 생성과 확인의 피드백 구조는 개선 필요

### 4.6 사용자 정의·설정

- 동물·연락처 사용자 정의 필드, 입소 양식, 문서·의료 태그, 드롭다운, 신청 진행 상태 제공
- Pet Defaults에서 종별 특성, 물리 특성, 관계 적합성, 설명, 기본 양식 등을 대량 설정
- 사용자 프로필에서 케이지 카드와 신청 관련 설정 제공

**판정**: 조직별 적응성은 높으나 설정 화면의 분산과 장문화가 초기 구축·유지보수 비용을 높임

## 7. 펫나우 제품 설계 시사점

1. **기능 수가 아닌 과업 연결 우선**  
   동물 등록→임보 배치→임보 기록→운영자 확인→입양 신청→계약·결제→상태 변경을 하나의 진행 맥락으로 연결할 필요

2. **역할별 작업대 구성**  
   운영자·임보자·입양 담당자에게 필요한 오늘의 업무, 차단 사유, 담당자, 기한을 우선 표시

3. **관리자 설정의 단계화**  
   10,000px 수준의 단일 설정 화면 대신 기본 설정, 고급 설정, 조직별 사용자 정의를 분리

4. **상태 변경 영향 범위 사전 안내**  
   Petstablished의 임보 지정→`Fostered` 변경 안내 방식 채택 가능

5. **모바일 완결성 기준 강화**  
   반응형 재배치 외에 모달, 파일 첨부, 저장, 오류 복구, 역할 간 확인까지 검증

6. **상업 기능과 운영 기능의 위계 분리**  
   결제·구매 기능은 운영 작업을 방해하지 않는 맥락에서 노출

7. **보고서 생성 상태의 실시간 피드백 제공**  
   백그라운드 생성 완료 알림, 예상 시간, 실패 사유, 재시도 기능 제공
