# 소구점 가설 및 ICE 점수 (v1 — Gina 인터뷰 반영)

## 개요

- 기반: `03_persona.md`, `05_value_promise.md`, `user_interview.md`
- 전략 축: 독립 SaaS 우선
- **v0 → v1 핵심 변경**: 1순위 가설이 바뀌었다. v0의 "독촉 해방"이 아니라 **"준비 상태 판단"**이 고객이 실제로 말한 문제였다.
- **광고 반응은 구매 의향이 아니라 문제 공감의 신호로만 해석한다.**

### ICE 산식
`ICE = Impact × Confidence × Ease` (각 1~10)

### H-A. 준비 상태 판단 — "어떤 개가 나갈 준비가 됐는지 압니까?" 🔻 **v1.1 재점수**

| 항목 | 내용 |
|---|---|
| 타겟 | 다이앤(대표) · 조(시스템 실무자) |
| 대응 Use Case | UC-11 |
| **로컬 공통 형태** | **의료·행동·미디어·법적 정보가 여러 사람에게 흩어져 있어 "이 개를 다음 단계로 보내도 되는지" 판단하지 못한다** |
| 크로스보더 요소 (제외) | ~~번역이 안 돼서~~, ~~양국 팀이 개를 직접 못 봐서~~ → `crossborder_reference.md` |
| 인터뷰 원문 (참고) | `"we don't know who's ready, what their status is, what their health status is"` |
| 로컬 공통 근거 | 딥리서치 인사이트 4 [Moderate] — "입양 지연은 신청서보다 **선행조건과 인계**에서 발생" / 병목 3위 |

| **Impact** | **8** ⬇ (v1 10) — 로컬 딥리서치에서는 병목 **3위**다. 크로스보더 증폭분을 제거하면 1위 근거가 사라진다 |

| **Ease** | **5** — 판단하려면 데이터가 다 들어와야 한다. 기존 CRM 병행이 어렵다 |
| **ICE** | **240** (v1 400) |

> **솔직한 재평가**: Gina 인터뷰는 이 문제가 **크로스보더에서 심각하다**는 걸 증명했지 **로컬에서 심각하다**는 걸 증명하지 않았다. 크로스보더에서는 언어·거리 때문에 "수년"이 됐지만, **로컬에서는 같은 문제가 "며칠"일 수 있다.** 그러면 통증 강도가 전혀 다르다.
>
> → **광고 A안의 목적은 정확히 이 차이를 재는 것이다.**

### 왜 1순위가 다시 H-B로 돌아왔나

| 단계 | 1순위 | 이유 |
|---|---|---|
| v0 | H-B 독촉 해방 | 리서치 기반. Ease가 압도적 |
| v1 | H-A 준비 상태 | 인터뷰에서 확인된 통증 |
| **v1.1** | **H-B 독촉 해방** | **인터뷰가 증명한 건 크로스보더 통증이었다.** 그걸 걷어내면 H-A의 로컬 근거는 딥리서치 [Moderate]로 되돌아간다 |

**핵심**: H-A와 H-D는 ICE가 240으로 같다. 근거 수준이 비슷해지면 **Ease가 순위를 가른다** — H-B는 기존 CRM을 끊지 않고 옆에 붙일 수 있어 전환 장벽 1·2·3을 모두 우회한다.

⚠️ 다만 H-A의 **Impact가 가장 높다(8)**. 로컬 공통성만 확인되면 즉시 1순위로 올라온다. **그래서 광고로 재는 것이다.**

## MECE 점검 (v1)

| 가설 | 다루는 축 |
|---|---|
| H-A | 모인 정보로 **판단**하는 문제 |
| H-B | 정보가 **들어오게** 하는 문제 (입력 주체 = 임보자) |
| H-C | 정보를 **밖으로 내보내는** 문제 (게시·연동) |
| H-D | 입력 자체의 **비용** (입력 주체 = 직원) |
| H-E | 정보를 **조회**하는 문제 |
| H-F | 사람이 **바뀔 때**의 비용 |
| H-G | **도입 시점** 1회성 리스크 |
| H-H | 조직 **밖 사용자**와의 연결 |

⚠️ H-A와 H-E는 경계가 겹친다(판단 vs 조회). 광고에서는 H-A만 쓰고 H-E는 제품 화면 요구사항으로 흡수한다.

## 검증 설계

### 광고에서 재는 것
- 디스커버리 콜 **예약 수** / 리드의 **ICP 부합률** / 가설별 예약 전환율 차이
- **CTR로 판단하지 않는다.** 클릭은 호기심, 예약은 문제 인식

### 가장 중요한 단일 질문
> **로컬 쉘터에서 "준비 상태 판단 실패"가 얼마나 아픈가?**
> - 크로스보더에서는 언어·거리 때문에 **"수년 대기"**가 됐다
> - 로컬에서는 같은 문제가 **"며칠 지연"**일 수 있다
> - 며칠이면 통증이 약하고, 몇 주면 강하다. **이 차이가 H-A의 진짜 Impact를 결정한다**

### 반증 조건

| 가설 | 무너지는 조건 |
|---|---|
| H-A | 로컬 쉘터가 "우린 누가 준비됐는지 대체로 안다" 또는 "며칠이면 해결된다"고 답할 때 → **크로스보더 특수로 확정** |
| H-B | foster 담당자가 "Airtable·문자로 충분하다"고 답할 때 |
| H-D | Intake 빈도가 낮아 시간 절감이 체감되지 않을 때 |
| 공통 | 3개 모두 예약 전환이 안 나오면 **문제가 아니라 ICP를 의심한다** |

### ⚠️ 해석상 절대 금지

- **크로스보더 조직의 반응을 로컬 신호로 섞지 않는다.** SPCA International 경로 리드가 A안에 반응해도 그건 이미 아는 사실의 재확인일 뿐이다
- 광고 리드의 조직 유형을 **예약 폼에서 반드시 분류**한다 (국내 단일 주 / 다주 / 크로스보더)
