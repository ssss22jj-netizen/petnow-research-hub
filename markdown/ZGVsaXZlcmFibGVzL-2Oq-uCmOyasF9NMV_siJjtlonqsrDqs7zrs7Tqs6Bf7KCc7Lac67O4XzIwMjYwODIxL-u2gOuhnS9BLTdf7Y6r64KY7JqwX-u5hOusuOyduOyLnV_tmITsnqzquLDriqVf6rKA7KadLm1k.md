# 펫나우 비문인식 현재 기능 및 M1 검증안

- 기준일: 2026.07.26
- 조사 범위: 펫나우 공개 제품·개발 문서, 공개 가격, 학술 논문, 독립 보도
- 판정 원칙: 공급사 주장, 학술 데이터셋 성능, Shelter CRM 현장 성능을 구분

> **프로젝트 범위 제외:** 본 문서는 별도 참고 조사자료. M1의 검증 대상은 쉘터 업무 현장의 핵심 페인포인트와 경쟁 CRM 대비 해결 효과이며, 비문인식 연동·생체정보 활용·수익화는 M1 범위에 포함하지 않음.

## 1. 결론

1. **펫나우의 B2B 생체인식 제품 Petify에는 `등록·검증·식별` 기능이 이미 존재**
   - 등록: 비문을 신규 개체 프로필에 등록
   - 검증: 촬영 개체와 지정된 기존 프로필의 동일 여부 확인
   - 식별: 촬영 개체와 일치하는 등록 프로필 검색
2. **`비문 촬영 → 기존 등록 개체 프로필 검색`은 공식 제품 설명과 개발 문서로 확인**
3. **현재 개발 중인 Shelter CRM에서 검색 결과가 해당 동물 기록을 즉시 여는지는 공개 자료로 확인 불가**
4. **임보·병원·쉘터 간 인계 확인은 Petify의 검증 기능과 직접 부합**
5. **켄넬 카드·마이크로칩 번호 입력 대체는 기술적으로 구현 가능하나 현재 Shelter CRM 기능으로 확인되지 않음**
6. **분실동물 보호자 검색은 Premium 요금제의 기능으로 명시돼 있으나 등록망 범위·보호자 연락정보 반환 방식·현장 회수율은 확인 필요**
7. **정확도 숫자만으로 현장 도입 여부 판단 불가**
   - 실제 쉘터에서는 촬영 성공률, 미등록 개체의 오매칭, 반복 촬영 시간, 다른 작업자·기기·날짜 간 재현성이 핵심 지표

| 근거 | 공개 성능 | 적용 시 유의사항 |
| --- | --- | --- |
| 펫나우 가격 페이지 | 약 20만 데이터 포인트에서 99.998% 이상 | 공급사 주장. 정확도의 정의, 개체 수, 갤러리 규모, 오수락률 기준 미공개 |
| 2021 IEEE Access 논문 | Rank-1 식별 98.972%; FAR 0.1%에서 검증률 72.2%, FAR 0.01%에서 63.5% | 폐쇄형 식별 정확도와 엄격한 오수락률 조건의 검증 성능이 크게 다를 수 있음을 제시 |
| 2024 IEEE Access 논문 | 개 비문 Rank-1 식별 99.8%, 검증 99.62% | 연구 데이터셋 결과. 실제 쉘터의 미등록 개체·움직임·질병·오염 조건과 동일하지 않음 |

### 정확도 관련 필수 확인 항목

- `99.998%`의 분모와 오류 정의
- 등록된 개체 중 하나를 찾는 폐쇄형 식별인지, 미등록 개체를 거절하는 개방형 식별인지
- 갤러리 개체 수 증가에 따른 오매칭률
- 촬영 시도 대비 품질 통과율
- 같은 개체의 다른 날짜·작업자·휴대전화 간 재식별률
- 코가 젖거나 더럽거나 손상된 개체, 움직임이 크거나 취급이 어려운 개체의 실패율
- 잘못된 보호자에게 연결되는 오수락의 허용 기준과 수동 확인 절차

## 7. M1 실험 설계

### 실험 목적

비문인식의 기술 정확도 홍보가 아니라 `번호 입력·마이크로칩 스캔 대비 현장 업무 개선` 검증

### 권장 표본

- 등록 개 50마리 이상
- 미등록 개 50마리 이상
- 작업자 5명 이상
- iOS·Android 기기 각 2종 이상
- 같은 개체를 서로 다른 날짜에 3회 이상 재촬영

### 측정 퍼널

`촬영 대상 → 촬영 시도 → 품질 통과 → 등록 또는 검색 성공 → 정확한 개체 프로필 반환 → Shelter CRM 기록 열기 → 후속 업무 완료`

| 지표 | 정의 | 초기 통과 기준안 |
| --- | --- | --- |
| 촬영 완료율 | 촬영 시도 중 품질 통과 비율 | 90% 이상 |
| 무보조 완료율 | 2인 보정 없이 완료한 비율 | 80% 이상 |
| 촬영시간 | 앱 실행부터 품질 통과까지 | 중앙값 30초 이하 |
| 등록 개체 재식별률 | 등록 개체 촬영 시 정확한 프로필 반환 비율 | 98% 이상 |
| 미등록 개체 오매칭률 | 미등록 개체를 기존 프로필로 잘못 반환한 비율 | 운영 허용치 별도 확정. 원칙적으로 0%에 근접 |
| 기록 연결 성공률 | 식별 결과가 정확한 Shelter CRM 기록을 여는 비율 | 99% 이상 |
| 기존 방식 대비 절감 | 번호 입력·칩 스캔 대비 완료시간 변화 | 30% 이상 단축 또는 오류 50% 이상 감소 |

> 초기 통과 기준은 시장 표준이 아니라 M1 의사결정용 작업 가설. 오수락은 보호자 개인정보 노출과 잘못된 인계 위험이 있어 평균 정확도보다 별도 관리 필요.

## 8. 펫나우 내부에서 즉시 확인할 사항

1. 현재 Shelter CRM 빌드에 Petify SDK·API가 연결돼 있는지
2. `식별 성공 → Shelter CRM 동물 상세 화면` 딥링크가 구현돼 있는지
3. Petify 개체 ID와 Shelter CRM 개체 ID의 기준 시스템이 무엇인지
4. 등록·검증·식별별 최근 90일 실사용 로그와 실패 사유가 있는지
5. 99.998%의 평가 프로토콜과 개방형 식별 결과가 있는지
6. Premium 식별 기능을 무료 CRM 사용자에게 제공할 때의 원가·과금 정책
7. 보호자 연락정보 반환 범위와 쉘터 직원의 접근권한
8. 생체정보·보호자정보의 삭제, 수정, 조직 간 이관, 보존기간 정책
9. 마이크로칩과 비문 정보가 불일치할 때의 우선 기준과 수동 해결 절차
10. 공격성·질병·코 손상 등 촬영 제외 조건과 대체 식별 절차

## 9. 전략적 시사점

- **비문인식은 별도 기능이 아니라 인계·조회·분실동물 확인의 실행 수단으로 제시 필요**
- **M1 핵심 질문은 “비문이 정확한가”보다 “어떤 반복 업무에서 기존 식별 방식보다 빠르고 안전한가”로 설정 필요**
- **초기 침투 지표와 생체정보 지표 분리 필요**
  - 침투: 도입 조직 수, 주간 활성 사용자, 활성 개체 수, 반복 업무 완료율
  - 생체정보: 등록률, 재식별률, 오매칭률, 촬영 실패율, Shelter CRM 기록 연결률
- **마이크로칩 대체 주장은 보류 필요**
  - 마이크로칩의 법적·표준 식별 역할과 비문의 비접촉 검색 편의는 서로 다른 가치
  - 초기 포지셔닝은 `마이크로칩이 없거나 읽히지 않을 때의 보완 검색`이 근거에 부합
- **무료 CRM을 통한 데이터 축적과 Petify의 등록 개체당 월 과금 구조 간 경제성 검토 필요**
