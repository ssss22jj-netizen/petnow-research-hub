## 핵심 VP (v1 — Gina 인터뷰 반영)

> ### 어떤 개가 나갈 준비가 됐는지, 물어보지 않아도 압니다.
> ### 그래서 개가 더 빨리 입양됩니다.

레스큐의 정보는 CRM이 아니라 **사람의 머리와 문자함과 슬랙 채널**에 흩어져 있다. 정보가 조각으로 들어오면 "이 개가 나갈 준비가 됐는지"를 판단할 수 없고, 판단하지 못하면 개는 그냥 대기한다 — 몇 년씩.

펫나우는 건강·행동·사진·영상·허가 정보를 한 개체 아래 모아 **준비 상태를 판단 가능한 형태로 만든다.**

### v0 → v1에서 바뀐 것

| | v0 | v1 |
|---|---|---|
| VP 초점 | 기록이 **들어오게** 하는 것 (입력) | 들어온 기록으로 **판단하게** 하는 것 |
| 최종 성과 | 독촉 감소 · 현황 파악 시간 | **`dogs adopted faster`** (고객이 반복해서 돌아온 표현) |

> **왜 바뀌었나**: 인터뷰에서 고객이 말한 문제는 "기록이 안 모인다"가 아니라 `"we don't know who's ready, what their status is"` 였다. 입력은 수단이고, 판단이 결과다.

## 페르소나별 VP

### 메건 (임보 코디네이터 · 챔피언)

> **"기록 보내주세요"를 다시 보내지 않아도 됩니다.**

- 임보자가 계정 없이 링크로 그날 기록을 남긴다
- 정상 항목은 한 번에 완료, 이상만 상세 입력
- 이상·미응답만 코디네이터 화면에 올라온다
- **약속하는 결과**: 주간 독촉 건수 감소, 기록 완료율 상승

### 다이앤 (대표 · 구매 결정권자)

> **지금 몇 마리가 어디에 있는지, 사람에게 묻지 않고 봅니다.**

- 동물별 현재 위치 · 다음 행동 · 담당자 · 기한 · 차단 사유가 한 화면에
- 법적·의료·행동·위치·입양 상태를 독립 축으로 표시
- 사람이 나가도 기록이 남는다
- **약속하는 결과**: 현황 파악 시간 감소, 입양 공개까지 걸리는 일수 단축

### 로버트 (임보자 · 사용자)

> **링크 하나, 30초면 오늘 몫이 끝납니다.**

- 계정도 앱도 필요 없다
- 오늘 할 일만 보이고, 정상이면 한 번에 완료
- 이상하면 그때만 자세히 남긴다

## VP를 뒷받침하는 근거

| VP 요소 | 근거 | 근거 수준 |
|---|---|---|
| 독촉이 실재한다 | 딥리서치 병목 2위, `"unable to make changes"` | Moderate |
| 임보자가 계정을 감당 못 한다 | Pawlytics 데모 — 임보자 보고가 운영자 기록으로 남아 구분 불가 | 1차 관찰 |
| 상태가 흩어져 있다 | `"using google spreadsheets"` (CRM 보유 상태), `"purely over email"` | Strong (우회 행동 실재) |
| 경쟁이 못 하고 있다 | 4사 모두 데이터 계층엔 있으나 **업무 화면으로 꺼내주지 않음** | Moderate |
| 입력 부담이 크다 | Shelterluv 8분 44초 / 37필드 vs ASM 2분 43초 / 11필드 | **실측** |

## 경쟁 대비 포지셔닝

### 하지 말아야 할 주장

| 금지 | 이유 |
|---|---|
| "경쟁사에 없는 기능" | 동물·의료·임보·계약·보고 — 4사 모두 있다. 기능표 빈칸 채우기는 방향 이탈 신호 |
| "경쟁사에 없는 데이터 구조" | 개체·사건 분리는 업계 표준이고 경쟁사 저장 구조에 이미 반영돼 있다 |
| "고객지원이 더 좋다" | Pawlytics 지원 만족도 4.9라는 반례 존재 |
| "비문 인식이 있다" | [Emerging]. 구매 이유가 아니라 Intake에 내장되는 보조 수단 |

### 해야 할 주장

> **같은 데이터를 "이 개가 나갈 준비가 됐는가"라는 판단으로 꺼내주는 제품이 없다.**

리뷰 근거(우회 행동), 데모 근거(실측 시간), 인터뷰 근거(`we don't know who's ready`)가 모두 이 방향을 가리킨다.

### ⚠️ 전환 장벽 순위 (v1.1 — 호환성을 분해한 뒤)

Gina는 호환성을 1순위로 답했지만 **KK9R 특수일 것**이라고 스스로 단서를 달았다. 분해하면 두 가지가 섞여 있다.

| 구성 요소 | 성격 | 처리 |
|---|---|---|
| 양국 파트너 기관 간 **서류·기록 호환** | 🔴 크로스보더 특수 | 제외 → `crossborder_reference.md` |
| **외부 게시 채널(Petfinder·Adopt-a-Pet·웹사이트) 종속** | 🟢 **미국 레스큐 공통** | 채택 |

**분해 근거**: Pawlytics가 탈락한 실제 이유는 국가 간 서류가 아니라 **API 반영이 12~24시간 걸린다**는 것이었다. 로컬 쉘터에도 그대로 적용된다 — 준비된 개를 실시간으로 외부에 노출하지 못하면 입양이 늦어진다.

### 최종 순위 (로컬 ICP 기준)

| 순위 | 장벽 | 근거 |
|---:|---|---|
| **1** | **외부 게시 API 종속** | 인터뷰(분해분) + 경쟁 분석. Shelterluv·Petstablished 모두 syndication이 핵심 가치 |
| 2 | 데이터 이전 / historical data | 리뷰 `"clear everything"` + Gina — 단 `"that's with any software"`라며 보편 조건 취급 |
| 3 | 재교육 비용 | 리뷰 `"a few months"`, `"get all the staff up to par"` |
| 4 | 결제·기부·마이크로칩 생태계 결합 | 경쟁 분석 |
| 5 | 현행 도구의 충분성 | 리서치 — 가장 과소평가됨 |

→ **외부 게시 연동은 마케팅 강점이 아니라 진입 필수조건이다.** 실시간 syndication이 없으면 나머지 가치는 논의 대상이 되지도 못한다.

### 아직 확인 안 된 것

위 순위는 **인터뷰 1건(크로스보더) + 리서치**에서 재구성한 것이다. 로컬 쉘터에서의 실제 순위는 미확인이다.

## 지불 정당화 구조 (독립 SaaS 축) — v1

### 확인된 현재 지출 (KK9R, n=1)

| 툴 | 비용 | 흡수 가능성 |
|---|---:|---|
| Petstablished | $42~50/월 | 외부 게시 API를 대체해야만 가능 |
| Pawlytics | $38/월 | 과거 데이터·백업 용도. 안정성 증명 시 |
| Airtable | ~$100/월 | foster diary·신청 workflow 흡수 시 |
| DocuSign | **$1,265/년 가능성** (전사 $12.65 표기 — 재확인 필요) | 계약·첨부·서명 지원 시. 단 6월경 연간 갱신 직후 |
| Slack·Zoom·Claude | 미확인 / ~$200 | 직접 대체 대상 아님 |

→ **이론상 흡수 가능 총액은 월 $180 이상**이다. 월 $99가 비싸다고 볼 근거는 현재 없다.

### 그러나 — WTP 증거는 아직 0이다

| 확인된 것 | 확인되지 않은 것 |
|---|---|
| 여러 SaaS에 실제로 돈을 쓰고 있다 | Shelter CRM에 **지불할 의사가 있는가** |
| 파일럿에 팀 전체가 참여할 계획이다 | 가격 범위 / $99에 대한 반응 |
| 무료 맞춤 개발에 강한 감사를 표했다 | 기존 SaaS 비용을 **이동시킬 의사** |
| | 예산 출처 · 승인자 · 결정 시점 |

> ⚠️ **가장 중요한 해석**: Gina는 `"No, I had no idea."` — 이 제품이 상용화될 계획인 줄 몰랐다. 현재의 호의는 **무료 맞춤 개발에 대한 감사**를 포함한다. 이를 구매 의향으로 읽으면 안 된다. WTP 증거는 **"호의적 관심" 1단계**를 넘지 않는다.

### 지불 정당화의 실제 축 (v1)

경쟁사 구독료 비교가 아니라, 고객이 말한 결과로 계산해야 한다.

| 가치 지표 | 계산 근거 | 필요한 baseline |
|---|---|---|
| **체류기간 단축** | 수년 대기하던 개가 몇 주 만에 게시되면 사료·의료·켄넬 비용이 직접 준다 | 파일럿 전 평균 체류일 |
| **입양 건수 증가** | `dogs adopted faster` — 게시 가능 개체 수 증가 | 월 게시 건수·입양 건수 |
| 툴 통합 | 위 표의 흡수 가능액 | 기능별 해지 조건 |

→ **파일럿 시작 전에 baseline을 측정해야 한다.** 안 하면 4주 뒤 개선을 증명할 방법이 없다. 파일럿은 다음 주 화요일 시작 예정이다.

## VP 검증 조건

이 VP가 참이려면 아래가 확인되어야 한다.

- [ ] 임보자가 실제로 링크 기반 기록을 **반복 사용**한다 (1회성 아님)
- [ ] 독촉 건수가 실제로 줄어든다
- [ ] 코디네이터가 줄어든 시간을 다른 일에 쓴다고 인식한다
- [ ] 대표가 그 결과에 **비용을 승인한다** (만족도 아님, 결제·계약·예산 배정 행동)
- [ ] 기존 CRM 병행이 새로운 이중 입력 부담을 만들지 않는다

**반증 조건**: 위 중 하나라도 무너지면 VP를 수정하거나 진입 과업을 UC-7로 옮긴다.
