# 비문 SaaS 메일 시퀀스 구성안

> 문구는 확정본이 아니라 이런 방향으로 작성한다는 예시. 최종 문구는 펫나우 검토 후 확정.

조니님 메일함(Apollo 연동)으로 발송 · 펫나우 external 그룹 참조 · 회신·예약·가입이 생기면 남은 메일 자동 중단 · 열람·클릭 추적 끔(판정은 회신 기준)

## 메일 시퀀스

| 시점 | 메일 | 역할 | 구성 |
|---|---|---|---|
| 10/13 | ① 첫 메일(수동) | 한 장짜리 랜딩: 무엇을, 어떻게, 얼마에 (링크 없이) | 회사별 한 줄 → 헤드라인·한 줄 설명 → 장면 3칸 → 등록·확인·기록 → 기존 앱·시스템 안에 넣는 방식 → 요금(등록 개체당 월 \$0.50~, 첫 50건 무료) → 관심 있으면 회신 요청 (링크·버튼 없음) |
| 10/15 | ② 후속 메일(자동, 같은 스레드) | 결정에 필요한 두 가지만 | 새 앱이 필요한가(아니요, 기존 시스템 안에) · 비용(등록 개체당 월 \$0.50~, 첫 50건 무료) → 버튼 2개 |
| 10/19 | ③ 마무리 메일(자동, 같은 스레드) | 마무리 + 담당자 소개 요청 | 짧은 텍스트, 버튼 없음, 회신만 유도 |
| 10/22 | 판정 | 의미 있는 리드 확보 여부 | 상담 진행 또는 가입 후 실제 API 호출 + 비문 적용 장면 확인 + 결정권자 참여 |

반응이 오면 아래 세 갈래 중 하나로 처리

- 30분 상담 예약 → 조니님 상담(30분): 지금 개체 확인이 필요한 업무 장면과 현재 처리 방법 / 비문을 넣을 앱·시스템과 연동할 개발 인력 / 도입을 결정하는 사람과 절차 / 무료 50건으로 시험할 범위와 다음 단계(API 키·기술 검토)
- 무료 가입 → 펫나우가 가입 확인 → 조니님 사용 지원 메일 (예제 코드·30분 세션 제안)
- 담당자 소개 → 소개받은 사람에게 조니님 개별 메일 1통: 첫 줄에 누가 소개했는지 명시 / 그 사람의 업무에 맞춘 장면 한 줄 / Petify 한 문장 설명 / 30분 상담 제안 + 무료로 써보기 링크

## 스팸함에 가지 않게 하는 원칙

메일의 내용 순서는 랜딩처럼 구성하되, 보이는 모양은 사람이 직접 쓴 일반 메일로 유지. 처음 연락하는 주소에서 광고 메일처럼 보이는 요소가 많을수록 받는 메일 서버가 스팸으로 분류할 가능성이 커짐.

| 원칙 | 이 시퀀스에 적용 | 근거 |
|---|---|---|
| 첫 메일에는 링크·이미지·첨부를 넣지 않음 | ① 첫 메일은 링크 0개, "관심 있으면 회신" 한 줄로 마무리. 상담·무료 가입 링크는 ② 후속 메일부터 | Apollo 도움말: 첫 접촉 메일의 링크·첨부·이미지는 수신 서버의 스팸 판정 가능성을 높임 |
| 메일당 링크는 1~2개 | ② 후속 메일은 상담·무료 가입 2개만, ③ 마무리 메일은 0개 | Apollo 도움말 |
| 디자인 요소 없이 일반 텍스트 형태로 작성 | 랜딩형 블록은 내용 순서로만 살리고, 배경색·표·이미지·버튼 모양 없이 문단과 줄바꿈으로 작성. 링크는 텍스트 링크 | Apollo는 사용자 HTML의 class 속성·head 안 스타일 등을 발송 전 제거. 광고형 HTML이 사람이 쓴 메일과 구분된다는 판단은 추정 |
| 서명에 링크·이미지를 넣지 않음 | 서명은 이름·직함·회사·실주소만 텍스트로. 수신 거부는 링크 대신 "더 받지 않으려면 회신" 문장으로 안내 | Apollo 도움말(서명 링크는 스팸 필터 유발 가능), FTC CAN-SPAM 안내(회신 이메일 방식의 수신 거부 허용) |
| 열람·클릭 추적 끔 | 시퀀스 전체 적용, 판정은 회신 기준 | 추적 픽셀은 스팸 분류 위험 요인. Snov.io 4,400만 건 분석에서 추적을 끈 메일의 회신율 2.36%, 켠 메일 1.08% |
| 하루 발송량을 낮게 시작 | 조니님 메일함 기준 하루 30~50통, 시간당 10통, 메일 간 간격 1~5분 | Apollo 발송 한도 도움말(평소 업무에 쓰는 메일함은 권장값보다 낮게) |
| 스팸 신고율 0.1% 미만 유지 | 발송 전 회사 웹사이트로 사업 내용·담당자를 확인해 관련 없는 곳 제외. 거절·불만 회신이 오면 해당 회사 즉시 제외 | Gmail 발송자 가이드라인: 0.1% 미만 권장, 0.3% 이상이면 받은편지함 도달에 큰 불이익 |
| 발송 도메인 인증 | 펫나우 도메인의 SPF·DKIM 설정 여부를 펫나우가 확인 | Gmail 발송자 가이드라인: 모든 발송자에게 SPF 또는 DKIM 요구 |

## 세그먼트별 페인포인트와 카피 방향

| 세그먼트 | 담당자의 골칫거리(공개 자료) | 카피 방향 예시 |
|---|---|---|
| 브리더·분양 플랫폼(1순위) | 사기 분양 글로 구매자가 모든 게시글을 의심. BBB 2025: 반려동물 검색 광고 링크의 최소 80%가 사기일 수 있음 | puppy scams and your listings / Show buyers the puppy is real, and the one they'll take home. |
| 펫 보험(1순위) | 보험 사기 증가(영국 2024년 적발 1만 3,823건, 전년 대비 132% 증가). 존재하지 않는 반려동물 가입, AI로 만든 사진·서류. 적발 사기의 90% 이상인 가입 전 질병 은폐는 비문으로 해결 안 됨 | checking pets at enrollment / Make sure the pet on the policy is real, and the one in the claim. |
| 펫 ID·분실동물(2순위) | 칩의 41.9% 미등록, 등록 칩의 35.4% 전화번호 오류(Ohio State 연구). 발견자에게 칩 리더기 없음 | found pets without a scanner / Let finders identify a pet with just a phone. |
| 펫 릴로케이션(2순위·탐색) | CDC 2024 규정: 고위험 국가 경유 시 칩이 안 읽히면 입국 거부·자비 반송, 대체 신원 수단 불인정. 비문은 국경 심사를 대신하지 못하며, 보완 가치는 업체 내부 운영(픽업~인도 동일 개체 기록) 쪽. 실제 수요는 회신으로 확인 | tracking which dog is which / Keep a record that it's the same dog, from pickup to delivery. |
| 해외 장거리 펫 운송(후보·조사 전) | 근거 조사 전. 차량 운송 중 개체 혼동·인계 분쟁을 가설로 둠. 국경을 넘지 않는 미국 내 이동이라 규정 충돌은 적을 것으로 추정. 소규모 사업자가 많아 API 연동 역량 확인 필요 | 릴로케이션과 같은 방향(픽업~인도 동일 개체 기록). 착수 시 조사 후 확정 |
| 펫케어 운영 소프트웨어(후보·조사 전) | 근거 조사 전. 고객사(데이케어·호텔)의 체크인 시 동물 혼동, 회원권 공유·도용을 가설로 둠. 데이케어 다수가 외부 소프트웨어를 쓴다는 전제도 확인 필요 | 체크인 확인 기능을 소프트웨어에 탑재해 고객사 전체에 제공하는 방향. 착수 시 조사 후 확정 |
