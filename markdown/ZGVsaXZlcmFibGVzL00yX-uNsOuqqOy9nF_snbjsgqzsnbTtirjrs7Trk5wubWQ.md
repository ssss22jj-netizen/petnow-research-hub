# M2 데모 콜 인사이트 보드

> 콜 종료 시마다 각 표에 한 행씩 추가한다. 이 보드가 답할 것은 두 가지다 — **①지불 가능한 수준의 통증인가 ②자사 제품을 해답으로 보는가.** 나머지 표는 두 판정의 판독 맥락이다.
>
> **표를 판정 항목별로 분리한 이유** — 한 표에 전 항목을 담으면 열 폭이 커져 콜 간 세로 비교가 불가능하다. 전 표의 앞 3열(`#`·소재·조직)을 동일하게 두어 항목별로만 대조되게 했다.
>
> 콜 원문은 `sources/interview-reports/` 정리본에 있다. 콜별 인사이트 문서를 포함한 **인터뷰 자료 전체는 [고객 인터뷰](#/library/interview) 페이지**에서 본다.

## 6. 6건 종합 판독

> 콜 6건 시점의 **잠정 판독.** 확정 판정 아님.

**① 통증의 공통 형태 — 다음 조치가 담당자 기억에만 존재**

- 표현은 콜마다 상이하나(다음 조치 / 재연락 대상 / 단절 지점 / 잔여 작업) 현행 해법은 6건 동일 — **기억·스프레드시트·회의·메시지의 수작업 연결**

**② 기존 시스템 교체 희망 전건 부재 → 포지셔닝은 대체재가 아닌 운영 레이어**

- 사용 도구 폐기 의사를 밝힌 응답자 없음. 반면 **상위 레이어 부착에는 전원 개방적**
- CAP·LTBHS는 core + add-on(PetPoint + Petszel) 구조를 이미 운영 — **선례 존재**

**③ 실질 경쟁 대상은 경쟁 SaaS가 아닌 종이·화이트보드**

- 존치 사유는 노후 관행이 아니라 **로그인·교육 불요, 일괄 가시성, 즉시 수정**
- 판정 기준 — **자사 화면의 조작량이 종이를 상회하는 시점에 도입 불가**

**④ 소재 A 가설 수정 — "준비 완료 개체 식별"이 아니라 그 후단**

- 준비 완료 판정을 통증으로 진술한 응답자 없음
- 반복 확인된 축은 **만기·지연·다음 조치·담당자** (`Stage → Outstanding Item → Next Action → Due Date`)

**⑤ 지불 의향 전건 미검증**

- 최상위인 CAP도 예산·수용 가격대 미확인 — **PoC 신호와 유료 전환 신호를 동일시하지 말 것**

**⑥ 자원봉사자 UX가 반복되는 도입 조건**

- 고령·기술 저숙련 임보자 상실 불가(Kzoo·CAP 명시) → **100% 이전을 성공 기준으로 설정 불가**, 기존 채널 병행 전제

**⑦ Audit Trail — 반응은 검증, 소구 위계는 보조**

- 2개 콜에서 독립 발생(LTBHS 선발견 질의 / CAP 선요구). 컴플라이언스가 아닌 **"누가 이미 수행했는가" 확인용 운영 기능**으로 언급
- 소재 주축 아님. **랜딩·데모 내 보조 배치** (카야 판정 2026-08-25)

**⑧ 도입 속도의 변수는 가격이 아니라 추진 주체와 마감일** — CAP 무료 Petszel 8개월 사례 판독

## 읽는 법

- **표 1·2를 우선 대조한다.** 통증 강도가 낮으면 제품 개선으로도 판매되지 않고, 솔루션 적합이 낮으면 통증 규모와 무관하게 자사 제품으로 해결되지 않는다. 두 항목이 동시에 높은 콜의 조건(소재·응답자 프로필)이 곧 ICP다

- **반복이 신호다.** 각 표를 세로로 훑어 복수 콜에 걸쳐 반복되는 통증·요청을 식별한다. 전 표의 앞 3열을 동일하게 둔 목적이 이 대조에 있다
