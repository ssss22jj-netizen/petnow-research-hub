# M2 데모 콜 인사이트 보드

> 콜 종료 시마다 각 표에 한 행씩 추가한다. 이 보드가 답할 것은 두 가지다 — **①지불 가능한 수준의 통증인가 ②자사 제품을 해답으로 보는가.**
>
> **1절이 판독, 2~5절이 그 근거다.** 표는 판정 항목별로 나누고 앞 3열(`#`·소재·조직)을 공통으로 두었다. 콜 간 비교는 각 표를 세로로 훑어서 한다.
>
> 콜별 인터뷰 자료는 [인터뷰 모음집](#/library/reports) 페이지에 있다 — 펫나우 팀 원본 정리본(PDF)과 콜별 인사이트 문서가 함께 들어 있다.

## 1. 종합 판독

| 판독 | 근거 · 함의 |
| --- | --- |
| **① 통증은 "누가 입양 준비됐나"가 아니라 정보가 사람 사이에서 끊기는 지점에 있다** | · 준비 완료 판정을 통증으로 진술한 응답자 **전건 없음.** 반복된 축은 만기·지연·다음 조치·담당자<br>· SBCAS 실무진 8인 공통 — 여러 사람이 한 동물의 정보를 만들지만 한곳에 모이지 않아 **입소 정보 부족이 입양 단계의 재조사로 돌아온다**<br>· 질문은 "이 임보자가 답했는가"에서 끝나지 않고 **"안 했는데 우리 중 누가 다시 연락하는가"**까지 이어진다(Maybel's) |
| **② 경쟁 상대가 종이·기억에서 이미 갖춰진 도구 조합으로 옮겨갔다** | · 사용 도구 폐기 의사를 밝힌 응답자 **전건 없음.** 반면 상위 레이어 부착에는 전원 개방적<br>· Asheville 은 필요 기능을 이미 도구 6종으로 해결 — 본인 표현 **"거미줄"**. `기존 도구 + Petify` 가 되면 가치가 없다고 직접 우려<br>· **판정 기준은 도구 수를 실제로 줄이는가.** LifeLine 도 같은 축 — Doobert 는 좋은데 PetPoint 와 안 이어져 결국 사람이 중간을 잇는다 |
| **③ 제품 기본값은 조직 규모가 가른다** | · 대형은 **예외만 상신** — 임보자 업데이트 대부분이 직원 개입 불필요(LifeLine, 임보자 1,500명 이상). 소형은 반대로 **추적 자체를 없애는 것**이 가치(Maybel's·Kzoo)<br>· **입력 단위와 기록 단위를 분리해야 한다** — 최종 기록이 개체별이어도 입력까지 개체별일 필요는 없다(PawSafe 한배 새끼)<br>· 자원봉사자 UX 가 도입 조건 — 고령·저숙련 임보자를 기술로 잃을 수 없어 **100% 이전은 성공 기준이 될 수 없다.** 업무 배정도 개인보다 팀 단위가 운영에 맞는다(SBCAS) |
| **④ 첫 계약 논의가 열렸고, 가격 저항선도 같이 드러났다** | · **SBCAS 가 계약 초안 송부를 요청.** 카운티 계약 지연 시 연계 비영리 경로, Chameleon 연동 불가 시 CSV 제공, `Karen Eval` 시트 공유까지 진전 — 제품 관심을 넘어선 첫 사례<br>· 반대편 저항선 — **$99/월은 100% 자원봉사 단체에 지속 불가능**(Maybel's). 규모별 밴드가 필요하다<br>· 수요 발생 계기가 규정일 수 있다 — PawSafe 가 소프트웨어를 찾은 직접 계기는 **뉴욕주 임보 기록 의무 강화**(법적 실체는 미검증) |

**미결 — 알파 MVP 설계가 대기 중인 결정**

- **wedge 범위** — 셸터 메디신 체크리스트(LTBHS)·의료 워크플로우(SBCAS)·임보 커뮤니케이션(Kzoo·CAP)이 한 제품인가. SBCAS 의료팀은 검사·재진 종료 전 조기 이동과 의료 문제 미전달을 **별도 문제**로 제기했다
- **기본값의 규모 분기** — 전건 검토가 부담이 되는 임보자 규모, 그리고 고정 주기(daily·weekly) vs 이벤트 기반(백신 만기·투약 종료) 발송
- **배정·입력 단위** — 개인 배정 전제를 팀 단위(SBCAS)로 바꿀 것인가. 사용자별 과금이면 공동 운영자 4인이 동일 권한인 조직(Maybel's)과 충돌한다
- **영상 업로드 경로** — Maybel's 요구에 사진과 영상이 함께 있으나 데모는 사진만 확인. 초기 pain 의 절반이 미검증

**다음 콜에서 받을 것**

- **가격·예산 소유자·결재 절차** — 전 콜 공통이고 실제로 질의한 콜이 아직 없다
- **Shelterluv 연동 범위**(Asheville) — `상태 변화 감지 → 자동 체크인 → 직원 승인 → 기록 반영`까지의 왕복. 단순 불러오기로는 도입 근거가 서지 않는다
- **CAP 전결 한도와 Jared 의 임보 프로세스 소유 여부** — "부서 예산으로 조기 도입" 결론 전체가 이 전제에 의존한다

**회신 대기**

- **LifeLine** — Program Manager 가 Director·Technology Director 에게 시연 후 내부 검토. 대형 조직 진입 경로의 첫 시험
- **Maybel's** — 사용자 수 제한 회신. 사용자별 과금 구조의 시장 적합성 판단에 직결

**별도 조사**

- **뉴욕주 임보 기록 의무의 법적 실체** — 조항·적용 범위·타 주 유사 규정. 규정 대응을 시장 진입 논리로 쓰려면 선행 검증이 필요하다

## 읽는 법

- **1절 종합 판독이 결론, 2~5절 표가 근거다.** 판독이 흔들리면 해당 근거 표의 열을 세로로 다시 훑는다
- **2·3절을 우선 대조한다.** 통증 강도가 낮으면 제품 개선으로도 판매되지 않고, 솔루션 적합이 낮으면 통증 규모와 무관하게 자사 제품으로 해결되지 않는다. 두 항목이 동시에 높은 콜의 조건(소재·응답자 프로필)이 곧 ICP다
- 「소재」 열의 `A`·`B` 는 M1 광고 소재, `T1` 은 트랙 1(네트워크 소개 유입)이다
- 판정 열은 등급만 싣는다. 그 등급의 근거와 단서(무엇을 대체하는가·전제가 무엇인가)는 바로 오른쪽 열에 있다
- **통증 강도는 판단 기준 주체를 함께 표기한다.** 응답자 본인의 통증과 전언으로 옮긴 제3자의 통증은 가중치가 다르다
- 5절 「특이사항」이 특정 콜에서만 비대해지면, 해당 콜의 인사이트 문서를 별도로 분리한다
